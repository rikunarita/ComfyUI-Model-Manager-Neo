# ComfyUI‑Model‑Manager‑Neo 使用指南（中文）

> 姊妹文档: [English](USAGE.md) · [日本語](USAGE.ja.md) · [繁體中文](USAGE.zh-TW.md)

ComfyUI‑Model‑Manager‑Neo 是一个为 ComfyUI 增加模型**浏览、下载、上传、编辑**
能力的自定义节点。它完全运行在 ComfyUI 进程内部：后端是 ComfyUI 服务器中的
一组 `aiohttp` 路由，前端是注入页面的单个打包 Vue 3 应用。扫描、哈希、
头部解析以及整个 ZipNN 压缩引擎等重活，都由仓库内附带的预构建 Rust 核心执行。

## 1. 安装

任选一种方式：

**Git clone（便于后续更新）**

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/rikunarita/ComfyUI-Model-Manager-Neo.git
```

**ComfyUI Registry（ComfyUI Manager / CLI）** —— Neo 已发布在
[ComfyUI Registry](https://registry.comfy.org/publishers/rikunarita7669/nodes/comfyui-model-manager-neo)（官方节点仓库），
节点名为 `comfyui-model-manager-neo`：在 ComfyUI-Manager 中搜索
**ComfyUI‑Model‑Manager‑Neo**，或用官方命令行安装：

```bash
comfy node install comfyui-model-manager-neo
```

**手动下载** —— 下载
[仓库压缩包](https://github.com/rikunarita/ComfyUI-Model-Manager-Neo/archive/refs/heads/main.zip)，
解压到 `ComfyUI/custom_nodes/`，并确认文件夹名为
`ComfyUI-Model-Manager-Neo`。

然后**重启 ComfyUI**。Python 依赖（`huggingface_hub`、`hf_xet`、
`modelscope_hub`、`markdownify`）会在首次启动时自动安装。Web 打包产物已预构建并附带在 `web/`，
Rust 核心已预构建并附带在 `native/native-bin/`，因此**运行本扩展既不需要
Node.js 也不需要编译器** —— 覆盖的平台见[引擎](#the-engine)一节。

## 2. 打开管理器

共有四个入口，效果相同：

| 入口                              | 位置                             |
| --------------------------------- | -------------------------------- |
| **顶栏「Model Manager Neo」按钮** | ComfyUI 顶栏（设置齿轮旁）       |
| **旧式菜单按钮**                  | 旧式菜单容器（如果你的前端仍有） |
| **Extensions 菜单**               | `Extensions → Model Manager Neo` |
| **命令面板**                      | `Comfy.ModelManager.Open` 命令   |

管理器是一个**非模态窗口**：它悬浮在 ComfyUI 之上，但画布保持完全可交互，
因此你可以一边浏览一边把模型拖到图上。窗口可以按标题栏拖动、按任意边/角
调整大小、用 ⤢ 按钮最大化。可以同时打开多个窗口，点击即置前。管理器窗口的
标题栏会实时显示模型库的总大小。

> 加载指示器**只作用于所属面板** —— 请求进行期间只有该窗口变暗模糊，
> 画布、顶栏和其他窗口都保持可用。

## 3. 两种布局

用顶栏第一个按钮（网格 ⇄ 文件夹图标）切换，或在
**设置 → Model Manager Neo → 外观 → 平铺布局**中预选默认布局。

### 平铺布局

所有类型的所有模型排成一个网格，配有工具栏：

- **搜索** —— 多词元「AND」匹配；`*` 可作通配符（`*anime*` 匹配任何包含
  `anime` 的名称）。词元可匹配文件名_或_子文件夹。
- **类型筛选** —— `All` 或某一个模型类型。
- **排序** —— 名称 / 最大 / 最新创建 / 最新修改 / 最近使用（打开模型或将其
  加入图中都会记录使用）。
- **卡片尺寸** —— Extra Large / Large / Medium / Small，或**自定义尺寸**
  （带宽/高滑杆的对话框，持久化保存在 ComfyUI 设置中）。

![平铺布局](../demo-assets/view-flat.avif)

### 文件夹布局

文件管理器式的树状视图，带面包屑（每一级都有文件夹小图标）。面包屑在根目录
不占空间 —— 只有路径变深时才展开。双击文件夹进入；用面包屑或 ↑ 按钮返回。
右键模型弹出上下文菜单（**打开**）。窗口变窄时，中间层级先省略号化，
工具栏改为纵向堆叠 —— 与平铺视图相同的响应式规则 —— 控件永远不会被裁掉。

![文件夹布局](../demo-assets/view-folders.avif)

搜索框旁边的一行提供**添加文件夹**（文件夹加号图标）：输入任意名称，
文件夹就会创建在你正在浏览的目录内（以 `_ZNN` / `_DeltaZNN` 结尾的名称
为 ZipNN 保留）。同一行还有**排序方式**与**卡片尺寸**选择器：文件夹视图
是「限定在单个文件夹的平铺视图 + 文件夹专属功能（上级导航、创建文件夹、
文件夹压缩）」，因此模型卡片在两种布局中的外观和行为完全一致 ——
包括悬停列中的加节点 / 复制 / 工作流 / 模型页按钮。

两种布局共享顶栏的**显示/隐藏隐藏文件**按钮（名称以 `.` 开头的文件和文件夹）。

## 4. 模型卡片

- **预览** —— 图片或循环视频；没有预览的模型显示玻璃质感的 **NO PREVIEW**
  图案。
- **角标**（左上） —— 模型类型与文件大小，随卡片缩放。
- **子目录标签** —— 存放在类型根目录之下的模型，会在名称上方显示所在子目录
  （两种布局一致）。
- **星标开关**（右上，每张卡片都有） —— 未加星为轮廓星，已加星为实心黄色星；
  点击切换，加星的模型/文件夹永远排在最前。
- **ZipNN 角按钮**（右上，星标旁） —— 一键压缩（或反色显示的解压），
  确认与进度和详情窗口按钮完全相同；在文件夹卡片上则执行文件夹批量操作。
- **文件夹卡片** —— 手绘的淡绿松石玻璃文件夹（_**Neo** 所以是青系_）。悬停时
  文件夹轻轻浮起，指针离开后立即恢复静止。类型根卡片还会显示
  **该类型的总大小**。
- **重复警告** —— 记录的 SHA256 与库中其他文件相同的模型，会在详情窗口
  显示红色警告及重复文件的路径。
- **智能收藏**（平铺视图） —— 把当前的搜索 + 类型筛选保存为命名收藏
  （按用户持久化），并可从收藏菜单一键重新应用；当前收藏以带清除/删除按钮的
  角标显示。保存与应用集成在同一个胶囊按钮 `[💾 收藏 ▾]` 中：软盘部分有
  独立的点击/键盘目标并打开保存对话框，其余部分打开应用/切换菜单。
- **卫生扫描**（顶栏按钮，两种布局都有） —— 纯本地清查（不联网、不算哈希），
  列出孤立的预览/笔记文件、没有任何预览的模型（附进入其编辑器的捷径）和
  空文件夹；勾选的条目经惯常的 Danger 确认后删除。
- **悬停操作**（平铺布局、大卡片） —— **添加节点**、**从预览加载工作流**、
  **打开模型页**（平台已知时按钮以来源平台 logo 为背景）。
- **拖到图上** —— 把任意卡片拖到画布：
  - 拖到空白画布：创建对应的加载器节点并选中该模型
  - 拖到已有节点：填充匹配的组合输入
  - 把 _embedding_ 拖到文本区域：追加 `(embedding:name:1.0)`
  - 拖动**预览图**：加载其中内嵌的工作流
- **双击 / 单击** —— 打开模型详情窗口。
- **提示** —— 悬停卡片显示其绝对路径。

卫生扫描把结果集中到一个对话框中，每个条目都经惯常的 Danger 确认后删除：

![卫生扫描](../demo-assets/hygiene-scan.avif)

## 5. 模型详情与编辑

![模型详情](../demo-assets/model-info.avif)

窗口显示预览（有多个预览时为轮播）、基本信息表和两个标签页。

| 行                                  | 含义                                               |
| ----------------------------------- | -------------------------------------------------- |
| Model Type                          | ComfyUI 模型文件夹分组                             |
| **Directory**                       | **以 `/` 结尾**的绝对目录 —— 例如 `…/models/unet/` |
| File Name                           | 不含扩展名的名称                                   |
| File Size / Created At / Updated At | 文件系统信息                                       |

### 查看

- **下载到本地** —— 操作行中的下载图标按钮会把模型文件按库中原名以附件形式
  保存到你的机器。整行操作按钮（ZipNN、星标、模型页、识别、添加节点、
  加载工作流、上传到 hub、本地下载、编辑、删除）共享同一按钮尺寸，排成单行
  横向滚动。
- **上传到 hub** —— 操作行中的上传图标按钮会以该模型预填打开共享上传向导：
  选择 Hugging Face 或 ModelScope 后，向导跳过类型/模型两步，直接落在已填好
  模型路径的上传表单。
- **复制行内容** —— 悬停基础信息表（类型、目录、子文件夹、文件名、大小、
  日期）或 Information 表的行时，该行末尾浮出复制按钮（sticky 单元格：行比面板
  宽而横向滚动时，按钮保持在可见范围的右缘）；一键将该行的值复制到剪贴板。
- **Description 标签** —— 渲染存放在模型旁 `*.md` 文件中的 Markdown。
  链接在新标签页打开。
- **Information 标签** —— 该模型所有已记录信息的表格（默认只读；编辑模式下
  铅笔图标会**在警告之后**打开它，保存表单会重写笔记的 front‑matter）。
  笔记的 YAML front‑matter（Civitai / Hugging Face / ModelScope 下载时写入）
  被解析成行：作者、基础模型、每个文件哈希（`AutoV1` … `SHA256_12`）、
  格式与精度、模型平台、可点击的模型页链接，以及**所有**预览图的 URL；
  解析器不认识的键在表格末尾逐字列出。没有 front‑matter 的模型逐字显示
  直接从 safetensors 头部读出的 `__metadata__` 块 —— 不做任何缓存或后台扫描。
- **张量区**（safetensors 模型） —— 从头部解析出的精确张量布局，按
  Hugging Face safetensors 查看器的样式渲染为可折叠的**文件夹树**：
  点分张量名按段分组，每个文件夹行带有折叠/展开该层的文件夹图标
  （初始全部折叠）及其张量/参数计数，叶子行保留名称尾部 / dtype / shape。
  超大节点会对叶子分页，并提供明确的_全部显示_操作。树由 Rust 核心预先分组，
  因此即便数万张量的 MoE 头部也能立即打开。

  ![张量树](../demo-assets/tensor-tree.avif)

- **打开模型页** —— 操作行中的按钮与卡片悬停列中的孪生按钮一样，
  只要笔记记录了平台，就以来源站（Civitai、Hugging Face 或 ModelScope）的
  logo 为按钮背景。

### 按哈希识别

模型详情操作行中的**哈希反查按钮**（HashReverse 图案图标）向 Civitai 目录
询问某个本地文件是哪个模型版本：先尝试笔记 front‑matter 中已记录的哈希
（`AutoV1` / `AutoV2` / `SHA256` / `CRC32` / `BLAKE3`），全部落空才对文件做
单遍哈希。命中时打开解析出的模型/版本及其基础模型、触发词、文件列表，
并附上官方 CLI 命中时打印的同一条 `civitai download` 命令（可一键复制）；
未命中则报告找不到匹配的模型版本。查询按文件、按需进行 —— 永远不会执行
全库扫描或哈希。

### 编辑

按**铅笔**进入编辑模式（窗口变成表单）：

![编辑模式](../demo-assets/model-edit.avif)

- **Model Type** —— 下拉框只列出你的 ComfyUI 实际拥有文件夹的类型。
- **Directory** —— 只读字段加**文件夹按钮**，后者打开一个嵌套的文件夹选择
  对话框，包含每个基础路径与子文件夹的树：

  ![文件夹选择器](../demo-assets/folder-picker.avif)

- **文件名** —— 接受**文件夹前缀**。输入 `subfolder/my-model`，保存时模型
  会被归档到 `…/models/unet/subfolder/`（缺失的文件夹会被创建）。
  `\ : * ? " < > |` 以及空 / `.` / `..` 段会被拒绝，后端还会在服务端
  重新检查路径穿越。
- **预览** —— 作为单一图集管理。编辑模式下，主预览旁/下方的内联滚动缩略图条
  负责管理：选定主图、左右移动条目、删除单张图片；戴**蓝圈**的缩略图就是
  保存时晋升为卡片**主**预览的那张（点击图块和 ‹ / › 箭头移动蓝圈）。
  条末尾的虚线图块用于添加本地图片文件作为新预览（图片会转换为 WebP，
  视频保持原格式），删光所有条目即让模型没有预览。进入编辑时蓝圈总是落在
  当前主图上，无论查看模式停在第几页；查看模式翻页绝不会重新指定主图。
- **描述** —— 按提示文字旁的**编辑（铅笔）图标**打开 Markdown 文本域；
  文本域失焦时保存：

- **保存 / 取消** —— 有未保存更改时取消会先询问确认。保存只发一个请求；
  所有变更（名称、类型、目录、预览、描述）按字段原子地应用。
- **删除**（红色垃圾桶） —— 确认对话框之后删除模型**及**其预览与笔记。

## 6. 下载模型

从顶栏打开**下载列表**，然后：

### 创建下载任务

1. 粘贴 **Civitai 模型页**、**Hugging Face repo/blob/tree**、
   **ModelScope 模型页**（`www.modelscope.ai`）或**直接文件链接**
   （`.safetensors`、`.ckpt`、`.gguf` 等），按 **Enter** 或搜索图标。
   Civitai 镜像主机 `civitai.red` 上的页面 URL 与 Civitai 行为完全一致。
2. 直接链接必须先选择 **Model Type**（只提供你的 ComfyUI 拥有的类型）；
   可选的 **Subfolder** 字段可以把文件放得更深。
3. Civitai/HF 页面会解析出一个或多个**版本**与**文件**；在工具栏选版本，
   在编辑器里选文件。

   ![解析结果](../demo-assets/download-resolved.avif)

   版本行下方的编辑器**左侧放预览、右侧放图集条**，其下依次是文件选择 +
   下载、元数据编辑器和描述/信息标签页，因此无论窗口多窄都不会有内容
   被挤出视野。

4. 在编辑器中可以设置目标类型/目录、文件名（允许文件夹前缀）、预览图 ——
   模型页提供的**整个图集**都会被保留，轮播中选中的那张将成为卡片的主预览
   —— 以及 Markdown 描述（Civitai/HF 的描述会被预填，包括触发词与 YAML
   元数据）。
5. **下载**启动后台任务。预览尽可能在浏览器端获取，否则在服务端获取；
   两者都失败时模型仍会下载，只是没有预览。对话框会显示目标卷的
   **剩余空间**，文件放不下时会警告（后端也会拒绝）。

### 模型名搜索（多平台）

当输入**不以** `https://` 开头时，同一输入框变为模型名搜索框：结果由
**Hugging Face**（左）、**ModelScope**（中）、**Civitai**（右）并行返回。
每行带有所有者的头像（或首字母徽章）、下载数和两个深链 —— 所有者名 →
所有者页，仓库名 → 模型页（悬停下划线，点击打开）；点击行内其他位置会把
该模型解析进编辑器。也接受普通的 `username/repo-name`。**Enter 总能一次
解析**：先取结果中的精确匹配，再把裸仓库 id 当作 Hugging Face 仓库解析，
最后取第一个非空列的首行；尚无结果 —— 或输入比屏上结果更新 —— 时，
Enter 会（重新）执行名称搜索而不是解析过期的行。搜索进行期间，结果区中央
显示「搜索中…」转轮。每列也支持翻页：滚到底部时，只要存在下一页就会出现
**「∨ 显示更多」**按钮，点一下追加该列的下一页。可以在
**设置 → Model Manager Neo → 搜索**中隐藏平台、选择各平台的**排序方式**
（默认为 Hugging Face 趋势、ModelScope 点赞、Civitai 评分最高）。

![多平台搜索](../demo-assets/search-columns.avif)

### 下载计划与安全检查

版本解析完成后，编辑器显示试运行计划：目标路径、声明大小、已发布的 SHA256、
平台 API 密钥是否已配置。Civitai 下载在完成时与已发布的 SHA256 校验
（不匹配则删除文件并让任务失败）；属于其他类型的随附文件（如 VAE）会被
路由到匹配的模型文件夹；当版本的基础模型与目标文件夹已记录的库不符，
或载荷是加载时可能执行代码的 pickle/归档格式时，会显示警告。对每个配置了
密钥的平台（Hugging Face、ModelScope、Civitai），窗口顶部会显示已连接的
账户。

### 灯箱中的生成元数据

放大 Civitai 来源模型的预览时，左侧显示图片，右侧显示解析出的生成元数据：
提示词、负面提示词、采样器、步数、CFG scale、种子、clip skip、尺寸、
基础模型和资源配方。

### 下载列表

两个分区 —— **外部下载**与**本地上传** —— 每行显示预览缩略图、进度条、
已传输/总大小和速度，以及**暂停 / 继续 / 删除**控制。删除会移除部分文件
和任务记录。暂停的下载用 HTTP `Range` 请求续传。

> 进度、暂停与完成状态在关闭窗口后依然存在：任务保存在后端，
> 通过 websocket 推送。

## 7. 上传到 Hugging Face / ModelScope

## 10. 多选与 ZipNN 压缩

### 选择文件

两种布局的工具栏都有**选择文件**开关（列表勾选图标）。开启期间，每张卡片和
文件夹的左上角显示圆形复选框；点击卡片变为勾选而不是打开。选中任意一项后，
窗口底部立即出现批量操作栏：

![选择模式](../demo-assets/selection-mode.avif)

- **加入工作流** —— 为每个选中的模型创建一个加载器节点；选中的_文件夹_
  递归贡献其中每个模型；
- **删除** —— Danger 确认后删除每个选中的模型（含预览与笔记）；
  选中的_文件夹_递归删除；
- **ZipNN 批量**（选中文件夹时） —— ZipNN 图案按钮：批量压缩/解压所选
  文件夹（见下文）；
- **ZipNN 增量压缩**（恰好选中两个未压缩模型时） —— 打开基础/微调选择器
  （见下文）；
- **上传到 Hugging Face / ModelScope**（选中文件夹时） —— 通过同一个上传
  对话框批量上传所选文件夹内的每个模型（保留子文件夹）；
- **星标**（选中文件夹时，仅图标） —— 所有选中文件夹都已加星时呈黄色
  （按下则全部取消）；否则只给未加星的加星；
- **清除选择** —— 取消所有勾选。退出该模式也会清除。

ZipNN 打包文件夹（`*_DeltaZNN`、旧式 `*_ZNN`）与普通文件夹永远不能同时
选中：一类已勾选时再添加另一类，会自动取消打包文件夹的选中并弹出警告通知。

### ZipNN 压缩

打开 `.safetensors` 模型后，预览与信息表之间就是 **ZipNN 按钮**。按下并
确认后，整个压缩作为 Rust 核心中的一个后台任务运行（内存映射流式处理 ——
峰值内存约为最大张量而非整个模型）：

- 任务运行期间按钮替换为**进度条**，且任务可随时取消；
- 成功后原文件被 `<name>.znn.safetensors` 取代；预览与笔记跟随改名，
  网格自动刷新；
- 打开已压缩模型时，同一按钮以**反色**显示，动作翻转为_解压_；
  按下并确认即还原普通 `.safetensors` 文件。

已压缩模型的信息表还会把单行 _File Size_ 换成**原始文件大小** /
**压缩后大小** / **占原始大小百分比**三行（压缩前大小在压缩时已记录进文件
元数据）。

![已压缩模型详情](../demo-assets/compressed-model.avif)

压缩文件遵循官方 ZipNN 布局（`znn_compressed_vectors` 元数据、Huffman 压缩
张量 —— Rust 核心覆盖**所有** safetensors dtype，见下文_dtype 覆盖与互操作_），
因此打过 `zipnn_safetensors()` 补丁的加载器可以透明读取兼容带文件。压缩是
**无损且经过验证的**：核心在压缩时记录源文件的 SHA‑256，还原时内联复核
（不匹配则保留压缩文件，并把产物移为 `.corrupt` 以供检查）；只有在
`.znn.safetensors` 写入并通过原子改名验证之后，普通 `.safetensors` 才会被
删除，失败的运行会清理其部分产物。可选的 **paranoid 模式**（默认关；
环境变量 `MM_ZNN_PARANOID=1`）会在删除原文件之前再解压一遍并比对。

#### dtype 覆盖与互操作

Rust 核心压缩 **safetensors 0.8 定义的每个 dtype**（全部 22 种），
分为两个互操作带：

| 带                         | dtype                                                                                                                           | 官方 ZipNN 0.5.4 工具的行为                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 上游兼容带（代码 1–30）    | `F32` `F16` `BF16` `F8_E4M3` `F8_E5M2`                                                                                          | 原样解压 Neo 的文件                                                          |
| Neo 扩展带（代码 128–146） | `F64` `C64` `I8` `U8` `BOOL` `I16` `U16` `I32` `U32` `I64` `U64` `F8_E4M3FNUZ` `F8_E5M2FNUZ` `F8_E8M0` `F4` `F6_E2M3` `F6_E3M2` | 以明确的 `ValueError: Unsupported Dtype` 拒绝 —— 绝不静默误解码（CI 已实证） |

包含扩展带张量的文件会被标记 `znn_neo_extended="1"`：Information 标签随即
显示 **Neo Extended** 徽章（附解释互操作性的工具提示）和汇总已存 dtype 的
**压缩方式**行（`bfloat16×412, uint8×3, …`），压缩确认框也会事先说明产物
将是 Neo 扩展格式。高位字节全为零的整数张量（小 `int32` 索引、掩码、
缩放表）还会使用截断模式 —— 全零字节平面从载荷中无损地去除（压缩器只去除
它已验证在整个张量范围内全为零的平面）。

<a id="the-engine"></a>

**没有安装步骤。** 引擎是 Neo 自己的**纯 Rust 核心**，以预构建二进制的形式
附带在仓库内（`native/native-bin/`），通过一次普通 `import` 加载 ——
在每个受支持的平台上都**无需 `pip install`、无需 C 编译器、无需联网、
无需等待**：

| 平台                            | 产物                                            | 要求                                                      |
| ------------------------------- | ----------------------------------------------- | --------------------------------------------------------- |
| Linux x86_64                    | `native-bin/linux-x86_64/mm_core.abi3.so`       | glibc ≥ 2.28（Debian 10 / Ubuntu 20.04+）                 |
| Linux aarch64                   | `native-bin/linux-aarch64/mm_core.abi3.so`      | glibc ≥ 2.28                                              |
| macOS（Intel 与 Apple Silicon） | `native-bin/macos-universal2/mm_core.abi3.so`   | 单个 fat 二进制 —— Intel macOS 10.12+ / Apple Silicon 11+ |
| Windows x86_64                  | `native-bin/windows-x86_64/mm_core.pyd`         | MSVC 构建                                                 |
| Linux x86_64（自由线程）        | `native-bin/linux-x86_64t/mm_core.abi3t.so`     | glibc ≥ 2.28，自由线程 CPython 3.15+                      |
| Linux aarch64（自由线程）       | `native-bin/linux-aarch64t/mm_core.abi3t.so`    | glibc ≥ 2.28，自由线程 CPython 3.15+                      |
| macOS（自由线程）               | `native-bin/macos-universal2t/mm_core.abi3t.so` | 单个 fat 二进制，自由线程 CPython 3.15+                   |
| Windows x86_64（自由线程）      | `native-bin/windows-x86_64t/mm_core.pyd`        | MSVC 构建，自由线程 CPython 3.15+                         |

每个平台一个二进制即支持 **CPython 3.12 及更新版本**（Python Stable ABI）；
自由线程构建由 `<tag>t` 的 **abi3t** 二进制支持（CPython 3.15+、PEP 803），
加载器会自动选择 —— 自由线程解释器无法加载普通 abi3 二进制。
与官方格式的互操作是 CI 关卡而非口头承诺：每次 push 都会与官方 pip
`zipnn` 0.5.4 双向交叉验证。在表格之外的平台上扩展仍然可以安装 ——
浏览、下载和哈希回退到纯 Python 路径 —— 而 ZipNN 操作和预览重编码会在
错误通知中报告加载器给出的确切原因，绝不静默失败。

### ZipNN 批量压缩（文件夹）

选择一个或多个文件夹，按批量操作栏中的 **ZipNN 图案按钮**（或用文件夹卡片的
角按钮）。确认后，文件夹树内的每个 `.safetensors` 模型都被压缩 —— 预览与
笔记跟随各自的模型 —— 每个压缩文件都被**移入打包文件夹
`<name>_DeltaZNN`**（原文件夹清空后消失）。已经就地压缩的模型（单模型按钮、自动压缩或旧版本产物）
不会被重新压缩，而是原样移入打包文件夹。打包文件夹是密封的：其中只能
存放 ZipNN 内容（`*.znn.*` 模型、`*.znn` 增量文件），普通模型的上传、下载和
移入都会被拒绝。打包文件夹的 ZipNN 按钮是**反色**的；按下即**批量解压**整个打包文件夹，
把所有内容移回以其命名的文件夹，并删除清空的打包文件夹。增量文件夹
（`<base>_DeltaZNN`）同样属于打包文件夹 —— 其反色按钮会还原其中每个微调模型。
模型类型根文件夹（`checkpoints` 等）的打包文件夹建在**自己内部**
（`<root>_DeltaZNN`），因为类型根的同级目录会落在 ComfyUI 文件夹映射之外；
方向自动检测：存在普通模型时压缩，只剩打包文件夹时解压。旧版本创建的打包文件夹
（`<name>_ZNN`）仍可解压回原名。任务运行期间按钮显示带百分比的圆环。
多个文件夹在一次确认之后依次执行。

### ZipNN 增量压缩（微调模型）

恰好选择两个普通 `.safetensors` 模型（基础 + 微调），按 **ZipNN 增量压缩**。
对话框询问哪个选择是**基础模型**，另一个即微调模型。确认后只把**差异**存入
`<base>_DeltaZNN/<ft>_delta_<base>.znn`（通常只有微调模型大小的百分之几），
并删除冗余的微调文件。增量文件的卡片按钮（反色图案）会把微调模型
**逐字节精确地**还原到基础模型旁边，并在增量文件夹清空后将其删除。还原需要
基础模型仍然存在，且增量文件记录了微调模型自己的 SHA‑256，因此还原全程
可验证。

![ZipNN 增量对话框](../demo-assets/zipnn-delta-dialog.avif)

## 11. 设置

ComfyUI **设置 → Model Manager Neo**：

### 密钥

- **Hugging Face API 密钥** / **Civitai API 密钥** / **ModelScope API 密钥** ——
  本地保存在扩展旁的 `private.key` 中（UI 中打码），
  `HF_TOKEN` / `CIVITAI_API_KEY` / `MODELSCOPE_API_TOKEN` 为环境变量后备。
  旧版本保存在 ComfyUI 用户设置中的密钥会在首次运行时自动迁移。

### 模型列表

- **排除模型类型（使用英文逗号隔开）** —— 从网格和选择器中隐藏这些类型。
- **包含隐藏文件（以 . 开头的文件或文件夹）** —— 与工具栏眼睛按钮相同。
- **监视模型文件夹的外部更改** —— 默认关闭。开启后，原生核心监视每个模型
  文件夹（500 ms 防抖），_其他_程序添加或删除模型时（向 `models/loras`
  执行 `cp`、第二个下载器、正在填满的挂载卷），受影响的列表在约 1.5 秒内
  刷新，而不必等待 30 秒的周期性重验证。网络挂载的文件夹会自动跳过
  （inotify 类监视器收不到 NFS/SMB 共享的事件），Linux 监视配额
  （`fs.inotify.max_user_watches`）耗尽时会带着日志警告退化为周期刷新；
  `MM_WATCH_ROOTS=1/0` 可覆盖该设置。监视器状态 —— 已布防的根目录、
  退化状态、事件计数 —— 由 `GET /model-manager/watch-status` 以只读方式提供。

### 搜索

- **在模型搜索中隐藏 Hugging Face / ModelScope / Civitai 结果** ——
  模型名搜索的每个平台列一个开关（隐藏的列绝不会被查询）。
- **各平台排序方式** —— 相应 API 接受的每个值；默认为 Hugging Face _趋势_、
  ModelScope _点赞_、Civitai _评分最高_。

### ZipNN

- **自动压缩超过此天数未使用的模型** —— 压缩 N 天未动过的模型（0 = 关闭）。
- **下载完成后自动压缩** —— 下载完成后立即压缩。

### 下载

- **提示执行时暂停下载** —— ComfyUI 执行提示词期间挂起传输，之后恢复。

### 外观

- **卡片尺寸** / **卡片尺寸表** —— 尺寸选择器的持久化（隐藏条目；
  通过自定义尺寸对话框编辑）。
- **平铺布局** —— 打开时的默认布局。
- **记录 UI 性能标记** —— 默认关闭。用 `performance.mark` 对网格
  重算/绘制和张量树构建插桩，并把样本保存在环形缓冲区中；在浏览器控制台用
  `__mmNeoPerf.summary()`（P50/P95/P99，毫秒）、`__mmNeoPerf.enable()` /
  `.disable()` / `.reset()` 读取和控制。

## 13. 故障排查

| 症状                                      | 原因 / 解决办法                                                                                                                                                   |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理器按钮不见了                          | 前端没有注册扩展 —— 检查 ComfyUI 日志中的导入错误，并确认文件夹名为 `ComfyUI-Model-Manager-Neo`                                                                   |
| `Hugging Face token not set`              | 在设置（或 `HF_TOKEN`）中配置令牌后重新打开对话框                                                                                                                 |
| 下载一直不开始                            | URL 可能需要鉴权（Civitai 受限模型）—— 设置 Civitai 密钥；任务行会显示服务器的错误文本                                                                            |
| 「Failed to update model: PathIndex …」   | 所选类型在这台机器上没有文件夹 —— 从下拉框中另选类型                                                                                                              |
| UI 没有样式 / 灰色方块                    | 你看到的是过期的 `web/` 打包产物；用 `pnpm build` 重新构建（仅开发时需要）                                                                                        |
| 预览显示 NO PREVIEW                       | 模型没有预览文件；在编辑模式中设置一张                                                                                                                            |
| ZipNN 报告「原生核心不可用: …」           | 消息中带有加载器给出的确切原因：平台不在[引擎表](#the-engine)之内，或 `native/native-bin/<tag>` 二进制缺失/损坏（重新克隆仓库）。浏览与下载不受影响，仍可正常使用 |
| 自由线程 Python 3.13/3.14 上 ZipNN 不可用 | abi3t（自由线程 Stable ABI，PEP 803）仅从 CPython 3.15 起存在 —— 通知会准确显示这一原因。请改用 GIL 构建（3.12+）或自由线程 3.15+；浏览与下载不受影响             |
| 动画预览失去了动画                        | Rust 核心之前的版本保存的预览被冻结在第一帧；重新保存预览（编辑模式）会将其重编码为动画 WebP                                                                      |
