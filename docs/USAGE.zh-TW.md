# ComfyUI‑Model‑Manager‑Neo 使用指南（繁體中文）

> 姊妹文件: [English](USAGE.md) · [日本語](USAGE.ja.md) · [简体中文](USAGE.zh-CN.md)

ComfyUI‑Model‑Manager‑Neo 是一個為 ComfyUI 增加模型**瀏覽、下載、上傳、編輯**
能力的自定義節點。它完全執行在 ComfyUI 程序內部：後端是 ComfyUI 伺服器中的
一組 `aiohttp` 路由，前端是注入頁面的單個打包 Vue 3 應用。掃描、雜湊、
頭部解析以及整個 ZipNN 壓縮引擎等重活，都由儲存庫內附帶的預建置 Rust 核心執行。

## 1. 安裝

任選一種方式：

**Git clone（便於後續更新）**

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/rikunarita/ComfyUI-Model-Manager-Neo.git
```

**ComfyUI Registry（ComfyUI Manager / CLI）** —— Neo 已釋出在
[ComfyUI Registry](https://registry.comfy.org/publishers/rikunarita7669/nodes/comfyui-model-manager-neo)（官方節點儲存庫），
節點名為 `comfyui-model-manager-neo`：在 ComfyUI-Manager 中搜尋
**ComfyUI‑Model‑Manager‑Neo**，或用官方命令列安裝：

```bash
comfy node install comfyui-model-manager-neo
```

**手動下載** —— 下載
[儲存庫壓縮檔](https://github.com/rikunarita/ComfyUI-Model-Manager-Neo/archive/refs/heads/main.zip)，
解壓縮到 `ComfyUI/custom_nodes/`，並確認資料夾名為
`ComfyUI-Model-Manager-Neo`。

然後**重啟 ComfyUI**。Python 相依（`huggingface_hub`、`hf_xet`、
`modelscope_hub`、`markdownify`）會在首次啟動時自動安裝。Web 打包產物已預建置並附帶在 `web/`，
Rust 核心已預建置並附帶在 `native/native-bin/`，因此**執行本擴充套件既不需要
Node.js 也不需要編譯器** —— 覆蓋的平台見[引擎](#the-engine)一節。

## 2. 開啟管理器

共有四個入口，效果相同：

| 入口                              | 位置                                    |
| --------------------------------- | --------------------------------------- |
| **頂欄「Model Manager Neo」按鈕** | ComfyUI 頂欄（設定齒輪旁）              |
| **主選單項目**                    | 直接點選 **Model Manager Neo** 項目開啟 |
| **舊式選單按鈕**                  | 舊式選單容器（如果你的前端仍有）        |
| **命令面板**                      | `Comfy.ModelManager.Open` 命令          |

管理器是一個**非模態視窗**：它懸浮在 ComfyUI 之上，但畫布保持完全可互動，
因此你可以一邊瀏覽一邊把模型拖到圖上。視窗可以按標題列拖動、按任意邊/角
調整大小、用 ⤢ 按鈕最大化。可以同時開啟多個視窗，點選即置前。管理器視窗的
標題列會實時顯示模型庫的總大小。

> 載入指示器**只作用於所屬面板** —— 請求進行期間只有該視窗變暗模糊，
> 畫布、頂欄和其他視窗都保持可用。

## 3. 兩種佈局

用頂欄第一個按鈕（網格 ⇄ 資料夾圖示）切換，或在
**設定 → Model Manager Neo → 外觀 → 平鋪佈局**中預選預設佈局。

### 平鋪佈局

所有類型的所有模型排成一個網格，配有工具列：

- **搜尋** —— 多詞元「AND」匹配；`*` 可作萬用字元（`*anime*` 匹配任何包含
  `anime` 的名稱）。詞元可匹配檔名_或_子資料夾。
- **類型篩選** —— `All` 或某一個模型類型。
- **排序** —— 名稱 / 最大 / 最新建立 / 最新修改 / 最近使用（開啟模型或將其
  加入圖中都會記錄使用）。
- **卡片尺寸** —— Extra Large / Large / Medium / Small，或**自定義尺寸**
  （頻寬/高滑桿的對話方塊，持久化儲存在 ComfyUI 設定中）。

![平鋪佈局](../demo-assets/view-flat.avif)

### 資料夾佈局

檔案管理器式的樹狀檢視，帶麵包屑（每一級都有資料夾小圖示）。麵包屑在根目錄
不佔空間 —— 只有路徑變深時才展開。雙擊資料夾進入；用麵包屑或 ↑ 按鈕返回。
右鍵模型彈出上下文選單（**開啟**）。視窗變窄時，中間層級先省略號化，
工具列改為縱向堆疊 —— 與平鋪檢視相同的響應式規則 —— 控制元件永遠不會被裁掉。

![資料夾佈局](../demo-assets/view-folders.avif)

搜尋框旁邊的一行提供**新增資料夾**（資料夾加號圖示）：輸入任意名稱，
資料夾就會建立在你正在瀏覽的目錄內（以 `_ZNN` / `_DeltaZNN` 結尾的名稱
為 ZipNN 保留）。同一行還有**排序方式**與**卡片尺寸**選擇器：資料夾檢視
是「限定在單個資料夾的平鋪檢視 + 資料夾專屬功能（上級導航、建立資料夾、
資料夾壓縮）」，因此模型卡片在兩種佈局中的外觀和行為完全一致 ——
包括懸停列中的加節點 / 工作流 / 模型頁按鈕。

兩種佈局共享頂欄的**顯示/隱藏隱藏檔案**按鈕（名稱以 `.` 開頭的檔案和資料夾）。

## 4. 模型卡片

- **預覽** —— 圖片或迴圈影片；沒有預覽的模型顯示玻璃質感的 **NO PREVIEW**
  圖案。
- **角標**（左上） —— 模型類型與檔案大小，隨卡片縮放。
- **子目錄標籤** —— 存放在類型根目錄之下的模型，會在名稱上方顯示所在子目錄
  （兩種佈局一致）。
- **星標開關**（右上，每張卡片都有） —— 未加星為輪廓星，已加星為實心黃色星；
  點選切換，加星的模型/資料夾永遠排在最前。
- **ZipNN 角按鈕**（右上，星標旁） —— 一鍵壓縮（或反色顯示的解壓縮），
  確認與進度和詳細視窗按鈕完全相同；在資料夾卡片上則執行資料夾批次操作。
- **資料夾卡片** —— 手繪的淡綠松石玻璃資料夾（_**Neo** 所以是青系_）。懸停時
  資料夾輕輕浮起，指標離開後立即恢復靜止。類型根卡片還會顯示
  **該類型的總大小**。
- **重複警告** —— 記錄的 SHA256 與庫中其他檔案相同的模型，會在詳細視窗
  顯示紅色警告及重複檔案的路徑。
- **智慧收藏**（平鋪檢視） —— 把當前的搜尋 + 類型篩選儲存為命名收藏
  （按使用者持久化），並可從收藏選單一鍵重新應用；當前收藏以帶清除/刪除按鈕的
  角標顯示。儲存與應用整合在同一個膠囊按鈕 `[💾 收藏 ▾]` 中：軟盤部分有
  獨立的點選/鍵盤目標並開啟儲存對話方塊，其餘部分開啟應用/切換選單。
- **衛生掃描**（頂欄按鈕，兩種佈局都有） —— 純本地清查（不聯網、不算雜湊），
  列出孤立的預覽/筆記檔案、沒有任何預覽的模型（附進入其編輯器的捷徑）和
  空資料夾；勾選的條目經慣常的 Danger 確認後刪除。
- **懸停操作**（平鋪佈局、大卡片） —— **新增節點**、**從預覽載入工作流**、
  **開啟模型頁**（平台已知時按鈕以來源平台 logo 為背景）。
- **拖到圖上** —— 把任意卡片拖到畫布：
  - 拖到空白畫布：建立對應的載入器節點並選取該模型
  - 拖到已有節點：填充匹配的組合輸入
  - 把 _embedding_ 拖到文字區域：追加 `(embedding:name:1.0)`
  - 拖動**預覽圖**：載入其中內嵌的工作流
- **雙擊 / 單擊** —— 開啟模型詳細視窗。
- **提示** —— 懸停卡片顯示其絕對路徑。

衛生掃描把結果集中到一個對話方塊中，每個條目都經慣常的 Danger 確認後刪除：

![衛生掃描](../demo-assets/hygiene-scan.avif)

## 5. 模型詳細與編輯

![模型詳細](../demo-assets/model-info.avif)

視窗顯示預覽（有多個預覽時為輪播）、基本資訊表和兩個標籤頁。

| 行                                  | 含義                                               |
| ----------------------------------- | -------------------------------------------------- |
| Model Type                          | ComfyUI 模型資料夾分組                             |
| **Directory**                       | **以 `/` 結尾**的絕對目錄 —— 例如 `…/models/unet/` |
| File Name                           | 不含副檔名的名稱                                   |
| File Size / Created At / Updated At | 檔案系統資訊                                       |

### 檢視

- **下載到本地** —— 操作行中的下載圖示按鈕會把模型檔案按庫中原名以附件形式
  儲存到你的機器。整行操作按鈕（ZipNN、星標、模型頁、識別、新增節點、
  載入工作流、上傳到 hub、本地下載、編輯、刪除）共享同一按鈕尺寸，排成單行
  橫向捲動。
- **上傳到 hub** —— 操作行中的上傳圖示按鈕會以該模型預填開啟共享上傳精靈：
  選擇 Hugging Face 或 ModelScope 後，精靈跳過類型/模型兩步，直接開啟已填好
  模型路徑的上傳表單。
- **複製列內容** —— 懸停基礎資訊表（類型、目錄、子資料夾、檔名、大小、日期）
  或 Information 表的列時，該列末尾浮出複製按鈕（sticky 儲存格：列比面板寬而
  橫向捲動時，按鈕保持在可見範圍的右緣）；一鍵將該列的值複製到剪貼簿。
- **Description 標籤** —— 渲染存放在模型旁 `*.md` 檔案中的 Markdown。
  連結在新標籤頁開啟。
- **Information 標籤** —— 該模型所有已記錄資訊的表格（預設只讀；編輯模式下
  鉛筆圖示會**在警告之後**開啟它，儲存表單會重寫筆記的 front‑matter）。
  筆記的 YAML front‑matter（Civitai / Hugging Face / ModelScope 下載時寫入）
  被解析成行：作者、基礎模型、每個檔案雜湊（`AutoV1` … `SHA256_12`）、
  格式與精度、模型平台、可點選的模型頁連結，以及**所有**預覽圖的 URL；
  解析器不認識的鍵在表格末尾逐字列出。沒有 front‑matter 的模型逐字顯示
  直接從 safetensors 頭部讀出的 `__metadata__` 塊 —— 不做任何快取或後臺掃描。
- **張量區**（safetensors 模型） —— 從頭部解析出的精確張量佈局，按
  Hugging Face safetensors 檢視器的樣式渲染為可摺疊的**資料夾樹**：
  點分張量名按段分組，每個資料夾行帶有摺疊/展開該層的資料夾圖示
  （初始全部摺疊）及其張量/引數計數，葉子行保留名稱尾部 / dtype / shape。
  超大資料夾會對葉子分頁，並提供明確的_全部顯示_操作。樹由 Rust 核心預先分組，
  因此即便數萬張量的 MoE 頭部也能立即開啟。

  ![張量樹](../demo-assets/tensor-tree.avif)

- **開啟模型頁** —— 操作行中的按鈕（與卡片懸停列中的按鈕相同），
  只要筆記記錄了平台，就以來源站（Civitai、Hugging Face 或 ModelScope）的
  logo 為按鈕背景。

### 按雜湊識別

模型詳細操作行中的**雜湊反查按鈕**（HashReverse 圖示）向 Civitai 目錄
詢問某個本地檔案是哪個模型版本：先嚐試筆記 front‑matter 中已記錄的雜湊
（`AutoV1` / `AutoV2` / `SHA256` / `CRC32` / `BLAKE3`），全部落空才對檔案做
單遍雜湊。命中時開啟解析出的模型/版本及其基礎模型、觸發詞、檔案列表，
並附上官方 CLI 命中時列印的同一條 `civitai download` 命令（可一鍵複製）；
未命中則報告找不到匹配的模型版本。查詢按檔案、按需進行 —— 永遠不會執行
全庫掃描或雜湊。

### 編輯

按**鉛筆**進入編輯模式（視窗變成表單）：

![編輯模式](../demo-assets/model-edit.avif)

- **Model Type** —— 下拉框只列出你的 ComfyUI 實際擁有資料夾的類型。
- **Directory** —— 只讀欄位加**資料夾按鈕**，後者開啟一個巢狀的資料夾選擇
  對話方塊，包含每個基礎路徑與子資料夾的樹：

  ![資料夾選擇器](../demo-assets/folder-picker.avif)

- **檔名** —— 接受**資料夾字首**。輸入 `subfolder/my-model`，儲存時模型
  會被歸檔到 `…/models/unet/subfolder/`（缺失的資料夾會被建立）。
  `\ : * ? " < > |` 以及空 / `.` / `..` 段會被拒絕，後端還會在服務端
  重新檢查路徑穿越。
- **預覽** —— 作為單一圖集管理。編輯模式下，主預覽旁/下方的內聯捲動縮圖條
  負責管理：選定主圖、左右移動條目、刪除單張圖片；帶**藍圈**的縮圖就是
  儲存後成為卡片**主**預覽的那張（點選圖塊和 ‹ / › 箭頭移動藍圈）。
  條末尾的虛線圖塊用於新增本地圖片檔案作為新預覽（圖片會轉換為 WebP，
  影片保持原格式），刪光所有條目即讓模型沒有預覽。進入編輯時藍圈總是落在
  當前主圖上，無論檢視模式停在第幾頁；檢視模式翻頁不會改變主圖的指定。
- **描述** —— 按提示文字旁的**編輯（鉛筆）圖示**開啟 Markdown 文字域；
  文字域失焦時儲存。

- **儲存 / 取消** —— 有未儲存更改時取消會先詢問確認。儲存只發一個請求；
  所有變更（名稱、類型、目錄、預覽、描述）按欄位原子地應用。
- **刪除**（紅色垃圾桶） —— 確認對話方塊之後刪除模型**及**其預覽與筆記。

## 6. 下載模型

從頂欄開啟**下載列表**，然後：

### 建立下載任務

1. 貼上 **Civitai 模型頁**、**Hugging Face repo/blob/tree**、
   **ModelScope 模型頁**（`www.modelscope.ai`）或**直接檔案連結**
   （`.safetensors`、`.ckpt`、`.gguf` 等），按 **Enter** 或搜尋圖示。
   Civitai 映象主機 `civitai.red` 上的頁面 URL 與 Civitai 行為完全一致。
2. 直接連結必須先選擇 **Model Type**（只提供你的 ComfyUI 擁有的類型）；
   可選的 **Subfolder** 欄位可以把檔案放得更深。
3. Civitai/HF 頁面會解析出一個或多個**版本**與**檔案**；在工具列選版本，
   在編輯器裡選檔案。

   ![解析結果](../demo-assets/download-resolved.avif)

   版本行下方的編輯器**左側放預覽、右側放圖集條**，其下依次是檔案選擇 +
   下載、中繼資料編輯器和描述/資訊標籤頁，因此視窗較窄時也不會有內容
   被擠出視野。

4. 在編輯器中可以設定目標類型/目錄、檔名（允許資料夾字首）、預覽圖
   以及 Markdown 描述。模型頁提供的**整個圖集**都會被保留，輪播中選取的
   那張將成為卡片的主預覽；Civitai/HF 的描述會被預填（包括觸發詞與
   YAML 中繼資料）。
5. **下載**啟動後臺任務。預覽儘可能在瀏覽器端獲取，否則在服務端獲取；
   兩者都失敗時模型仍會下載，只是沒有預覽。對話方塊會顯示目標卷的
   **剩餘空間**，檔案放不下時會警告（後端也會拒絕）。

### 模型名搜尋（多平台）

當輸入**不以** `https://` 開頭時，同一輸入框變為模型名搜尋框：結果由
**Hugging Face**（左）、**ModelScope**（中）、**Civitai**（右）並行返回。
每行帶有所有者的頭像（或首字母徽章）、下載數和兩個深鏈 —— 所有者名 →
所有者頁，儲存庫名 → 模型頁（懸停下劃線，點選開啟）；點選行內其他位置會把
該模型載入編輯器。也接受普通的 `username/repo-name`。**Enter 總能一次
解析**：先取結果中的精確匹配，再把裸儲存庫 id 當作 Hugging Face 儲存庫解析，
最後取第一個非空列的首行；尚無結果 —— 或輸入比屏上結果更新 —— 時，
Enter 會（重新）執行名稱搜尋而不是解析過期的行。搜尋進行期間，結果區中央
顯示「搜尋中…」轉輪。每列也支援翻頁：滾到底部時，只要存在下一頁就會出現
**「∨ 顯示更多」**按鈕，點一下追加該列的下一頁。可以在

## 10. 多選與 ZipNN 壓縮

### 選擇檔案

兩種佈局的工具列都有**選擇檔案**開關（列表勾選圖示）。開啟期間，每張卡片和
資料夾的左上角顯示圓形核取方塊；點選卡片變為勾選而不是開啟。選取任意一項後，
視窗底部立即出現批次操作欄：

![選擇模式](../demo-assets/selection-mode.avif)

- **加入工作流** —— 為每個選取的模型建立一個載入器節點；選取_資料夾_時，
  其內部的每個模型（遞迴）都會成為對象；
- **刪除** —— Danger 確認後刪除每個選取的模型（含預覽與筆記）；
  選取的_資料夾_遞迴刪除；
- **ZipNN 批次**（選取資料夾時） —— ZipNN 按鈕：批次壓縮/解壓縮所選
  資料夾（見下文）；
- **ZipNN 增量壓縮**（恰好選取兩個未壓縮模型時） —— 開啟基礎/微調選擇器
  （見下文）；
- **上傳到 Hugging Face / ModelScope**（選取資料夾時） —— 透過同一個上傳
  對話方塊批次上傳所選資料夾內的每個模型（保留子資料夾）；
- **星標**（選取資料夾時，僅圖示） —— 所有選取資料夾都已加星時呈黃色
  （按下則全部取消）；否則只給未加星的加星；
- **清除選擇** —— 取消所有勾選。退出該模式也會清除。

ZipNN 打包資料夾（`*_DeltaZNN`、舊式 `*_ZNN`）與普通資料夾永遠不能同時
選取：混合勾選會彈出警告通知，打包資料夾一側保持未選取。

### ZipNN 壓縮

開啟 `.safetensors` 模型後，預覽與資訊表之間就是 **ZipNN 按鈕**。按下並
確認後，整個壓縮作為 Rust 核心中的一個後臺任務執行（記憶體對映流式處理 ——
峰值記憶體約為最大張量而非整個模型）：

- 任務執行期間按鈕替換為**進度條**，且任務可隨時取消；
- 成功後原檔案被 `<name>.znn.safetensors` 取代；預覽與筆記跟隨改名，
  網格自動重新整理；
- 開啟已壓縮模型時，同一按鈕以**反色**顯示，動作翻轉為_解壓縮_；
  按下並確認即還原普通 `.safetensors` 檔案。

已壓縮模型的資訊表還會把單行 _File Size_ 換成**原始檔案大小** /
**壓縮後大小** / **佔原始大小百分比**三行（壓縮前大小在壓縮時已記錄進檔案
中繼資料）。

![已壓縮模型詳細](../demo-assets/compressed-model.avif)

壓縮檔案遵循官方 ZipNN 佈局（`znn_compressed_vectors` 中繼資料、Huffman 壓縮
張量 —— Rust 核心覆蓋**所有** safetensors dtype，見下文_dtype 覆蓋與互操作_），
因此打過 `zipnn_safetensors()` 補丁的載入器可以透明讀取相容帶檔案。壓縮是
**無損且經過驗證的**：核心在壓縮時記錄原始檔的 SHA‑256，還原時內聯複核
（不匹配則保留壓縮檔案，並把產物移為 `.corrupt` 以供檢查）；只有在
`.znn.safetensors` 寫入並透過原子改名驗證之後，普通 `.safetensors` 才會被
刪除，失敗的執行會清理其部分產物。可選的 **paranoid 模式**（預設關；
環境變數 `MM_ZNN_PARANOID=1`）會在刪除原檔案之前再解壓縮一遍並比對。

#### dtype 覆蓋與互操作

Rust 核心壓縮 **safetensors 0.8 定義的每個 dtype**（全部 22 種），
分為兩個互操作帶：

| 帶                               | dtype                                                                                                                           | 官方 ZipNN 0.5.4 工具的行為                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 上游相容帶（程式碼 1–30）        | `F32` `F16` `BF16` `F8_E4M3` `F8_E5M2`                                                                                          | 原樣解壓縮 Neo 的檔案                                                        |
| Neo 擴充套件帶（程式碼 128–146） | `F64` `C64` `I8` `U8` `BOOL` `I16` `U16` `I32` `U32` `I64` `U64` `F8_E4M3FNUZ` `F8_E5M2FNUZ` `F8_E8M0` `F4` `F6_E2M3` `F6_E3M2` | 以明確的 `ValueError: Unsupported Dtype` 拒絕 —— 絕不靜默誤解碼（CI 已實證） |

包含擴充套件帶張量的檔案會被標記 `znn_neo_extended="1"`：Information 標籤隨即
顯示 **Neo Extended** 徽章（附解釋互操作性的工具提示）和彙總已存 dtype 的
**壓縮方式**行（`bfloat16×412, uint8×3, …`），壓縮確認框也會事先說明產物
將是 Neo 擴充套件格式。高位位元組全為零的整數張量（小 `int32` 索引、掩碼、
縮放表）還會使用截斷模式 —— 全零位元組平面從載荷中無損地去除（壓縮器只去除
它已驗證在整個張量範圍內全為零的平面）。

<a id="the-engine"></a>

**沒有安裝步驟。** 引擎是 Neo 自己的**純 Rust 核心**，以預建置二進位的形式
附帶在儲存庫內（`native/native-bin/`），透過一次普通 `import` 載入 ——
在每個受支援的平台上都**無需 `pip install`、無需 C 編譯器、無需聯網**：

| 平台                            | 產物                                            | 要求                                                      |
| ------------------------------- | ----------------------------------------------- | --------------------------------------------------------- |
| Linux x86_64                    | `native-bin/linux-x86_64/mm_core.abi3.so`       | glibc ≥ 2.28（Debian 10 / Ubuntu 20.04+）                 |
| Linux aarch64                   | `native-bin/linux-aarch64/mm_core.abi3.so`      | glibc ≥ 2.28                                              |
| macOS（Intel 與 Apple Silicon） | `native-bin/macos-universal2/mm_core.abi3.so`   | 單個 fat 二進位 —— Intel macOS 10.12+ / Apple Silicon 11+ |
| Windows x86_64                  | `native-bin/windows-x86_64/mm_core.pyd`         | MSVC 建置                                                 |
| Linux x86_64（自由執行緒）      | `native-bin/linux-x86_64t/mm_core.abi3t.so`     | glibc ≥ 2.28，自由執行緒 CPython 3.15+                    |
| Linux aarch64（自由執行緒）     | `native-bin/linux-aarch64t/mm_core.abi3t.so`    | glibc ≥ 2.28，自由執行緒 CPython 3.15+                    |
| macOS（自由執行緒）             | `native-bin/macos-universal2t/mm_core.abi3t.so` | 單個 fat 二進位，自由執行緒 CPython 3.15+                 |
| Windows x86_64（自由執行緒）    | `native-bin/windows-x86_64t/mm_core.pyd`        | MSVC 建置，自由執行緒 CPython 3.15+                       |

每個平台一個二進位即支援 **CPython 3.12 及更新版本**（Python Stable ABI）；
自由執行緒建置由 `<tag>t` 的 **abi3t** 二進位支援（CPython 3.15+、PEP 803），
載入器會自動選擇 —— 自由執行緒直譯器無法載入普通 abi3 二進位。
與官方格式的互操作由 CI 強制執行：每次 push 都會與官方 pip
`zipnn` 0.5.4 雙向交叉驗證。在表格之外的平台上擴充套件仍然可以安裝 ——
瀏覽、下載和雜湊回退到純 Python 路徑 —— 而 ZipNN 操作和預覽重編碼會在
錯誤通知中報告載入器給出的確切原因，絕不靜默失敗。

### ZipNN 批次壓縮（資料夾）

選擇一個或多個資料夾，按批次操作欄中的 **ZipNN 按鈕**（或用資料夾卡片的
角按鈕）。確認後，資料夾樹內的每個 `.safetensors` 模型都被壓縮 —— 預覽與
筆記跟隨各自的模型 —— 每個壓縮檔案都被**移入打包資料夾
`<name>_DeltaZNN`**（原資料夾清空後消失）。已經就地壓縮的模型（單模型按鈕、自動壓縮或舊版本產物）
不會被重新壓縮，而是原樣移入打包資料夾。打包資料夾是密封的：其中只能
存放 ZipNN 內容（`*.znn.*` 模型、`*.znn` 增量檔案），普通模型的上傳、下載和
移入都會被拒絕。打包資料夾的 ZipNN 按鈕是**反色**的；按下即**批次解壓縮**整個打包資料夾，
把所有內容移回以其命名的資料夾，並刪除清空的打包資料夾。增量資料夾
（`<base>_DeltaZNN`）同樣屬於打包資料夾 —— 其反色按鈕會還原其中每個微調模型。
模型類型根資料夾（`checkpoints` 等）的打包資料夾建在**自己內部**
（`<root>_DeltaZNN`），因為類型根的同級目錄會落在 ComfyUI 資料夾對映之外；
方向自動檢測：存在普通模型時壓縮，只剩打包資料夾時解壓縮。舊版本建立的打包資料夾
（`<name>_ZNN`）仍可解壓縮回原名。任務執行期間按鈕顯示帶百分比的圓環。
多個資料夾在一次確認之後依次執行。

### ZipNN 增量壓縮（微調模型）

恰好選擇兩個普通 `.safetensors` 模型（基礎 + 微調），按 **ZipNN 增量壓縮**。
對話方塊詢問哪個選擇是**基礎模型**，另一個即微調模型。確認後只把**差異**存入
`<base>_DeltaZNN/<ft>_delta_<base>.znn`（通常只有微調模型大小的百分之幾），
並刪除冗餘的微調檔案。增量檔案的卡片按鈕（反色顯示）會把微調模型
**逐位元組精確地**還原到基礎模型旁邊，並在增量資料夾清空後將其刪除。還原需要
基礎模型仍然存在，且增量檔案記錄了微調模型自己的 SHA‑256，因此還原全程
可驗證。

![ZipNN 增量對話方塊](../demo-assets/zipnn-delta-dialog.avif)

### 金鑰

### 模型列表

- **排除模型類型（使用英文逗號隔開）** —— 從網格和選擇器中隱藏這些類型。
- **包含隱藏檔案（以 . 開頭的檔案或資料夾）** —— 與工具列眼睛按鈕相同。
- **監視模型資料夾的外部更改** —— 預設關閉。開啟後，原生核心監視每個模型
  資料夾（500 ms 防抖），_其他_程式新增或刪除模型時（向 `models/loras`
  執行 `cp`、第二個下載器、正在填滿的掛載卷），受影響的列表在約 1.5 秒內
  重新整理，而不必等待 30 秒的週期性重驗證。網路掛載的資料夾會自動跳過
  （inotify 類監視器收不到 NFS/SMB 共享的事件），Linux 監視配額
  （`fs.inotify.max_user_watches`）耗盡時會帶著日誌警告退化為週期重新整理；
  `MM_WATCH_ROOTS=1/0` 可覆蓋該設定。監視器狀態 —— 監視中的根目錄、
  退化狀態、事件計數 —— 由 `GET /model-manager/watch-status` 以只讀方式提供。

### 搜尋

- **在模型搜尋中隱藏 Hugging Face / ModelScope / Civitai 結果** ——
  模型名搜尋的每個平台列一個開關（隱藏的列絕不會被查詢）。
- **各平台排序方式** —— 相應 API 接受的任意值；預設為 Hugging Face _趨勢_、
  ModelScope _點贊_、Civitai _評分最高_。

### ZipNN

- **自動壓縮超過此天數未使用的模型** —— 壓縮 N 天未動過的模型（0 = 關閉）。
- **下載完成後自動壓縮** —— 下載完成後立即壓縮。

### 下載

- **提示執行時暫停下載** —— ComfyUI 執行提示詞期間掛起傳輸，之後恢復。

### 外觀

- **卡片尺寸** / **卡片尺寸表** —— 尺寸選擇器把所選尺寸儲存在這裡。
  這兩個條目不會出現在設定列表中；請透過自定義尺寸對話方塊修改。
- **平鋪佈局** —— 開啟時的預設佈局。
- **記錄 UI 效能標記** —— 預設關閉。用 `performance.mark` 對網格
  重算/繪製和張量樹建置插樁，並把樣本儲存在環形緩衝區中；在瀏覽器控制檯用
  `__mmNeoPerf.summary()`（P50/P95/P99，毫秒）、`__mmNeoPerf.enable()` /
  `.disable()` / `.reset()` 讀取和控制。

## 13. 疑難排解

| 症狀                                        | 原因 / 解決辦法                                                                                                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理器按鈕不見了                            | 前端沒有註冊擴充套件 —— 檢查 ComfyUI 日誌中的匯入錯誤，並確認資料夾名為 `ComfyUI-Model-Manager-Neo`                                                                 |
| `Hugging Face token not set`                | 在設定（或 `HF_TOKEN`）中配置權杖後重新開啟對話方塊                                                                                                                 |
| 下載一直不開始                              | URL 可能需要鑑權（Civitai 受限模型）—— 設定 Civitai 金鑰；任務行會顯示伺服器的錯誤文字                                                                              |
| 「Failed to update model: PathIndex …」     | 所選類型在這臺機器上沒有資料夾 —— 從下拉框中另選類型                                                                                                                |
| UI 沒有樣式 / 灰色方塊                      | 你看到的是過期的 `web/` 打包產物；用 `pnpm build` 重新建置（僅開發時需要）                                                                                          |
| 預覽顯示 NO PREVIEW                         | 模型沒有預覽檔案；在編輯模式中設定一張                                                                                                                              |
| ZipNN 報告「原生核心不可用: …」             | 訊息中帶有載入器給出的確切原因：平台不在[引擎表](#the-engine)之內，或 `native/native-bin/<tag>` 二進位缺失/損壞（重新克隆儲存庫）。瀏覽與下載不受影響，仍可正常使用 |
| 自由執行緒 Python 3.13/3.14 上 ZipNN 不可用 | abi3t（自由執行緒 Stable ABI，PEP 803）僅從 CPython 3.15 起存在 —— 通知會準確顯示這一原因。請改用 GIL 建置（3.12+）或自由執行緒 3.15+；瀏覽與下載不受影響           |
| 動畫預覽失去了動畫                          | Rust 核心之前的版本儲存的預覽被凍結在第一幀；重新儲存預覽（編輯模式）會將其重編碼為動畫 WebP                                                                        |
