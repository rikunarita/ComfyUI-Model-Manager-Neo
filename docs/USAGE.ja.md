# ComfyUI‑Model‑Manager‑Neo 使い方ガイド（日本語）

> 姉妹ドキュメント: [English](USAGE.md) · [简体中文](USAGE.zh-CN.md) · [繁體中文](USAGE.zh-TW.md)

ComfyUI‑Model‑Manager‑Neo は、ComfyUI にモデルの**閲覧・ダウンロード・
アップロード・編集**機能を追加するカスタムノードです。ComfyUI プロセスの外には
一切出ません: バックエンドは ComfyUI サーバ内の `aiohttp` ルート群、
フロントエンドはページに注入される単一のバンドル済み Vue 3 アプリです。
スキャン・ハッシュ・ヘッダ解析・ZipNN 圧縮エンジン全体といった重い処理は、
リポジトリに同梱されたプリビルドの Rust コアが実行します。

## 1. インストール

いずれかの方法で導入してください:

**Git クローン（アップデート推奨）**

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/rikunarita/ComfyUI-Model-Manager-Neo.git
```

**ComfyUI レジストリ（ComfyUI Manager / CLI）** — Neo は
[ComfyUI レジストリ](https://registry.comfy.org/publishers/rikunarita7669/nodes/comfyui-model-manager-neo)
（公式ノードカタログ）に `comfyui-model-manager-neo` として公開されています:
ComfyUI-Manager で **ComfyUI‑Model‑Manager‑Neo** を検索するか、
公式 CLI からインストールできます:

```bash
comfy node install comfyui-model-manager-neo
```

**手動ダウンロード** —
[リポジトリのアーカイブ](https://github.com/rikunarita/ComfyUI-Model-Manager-Neo/archive/refs/heads/main.zip)
をダウンロードして `ComfyUI/custom_nodes/` に展開し、フォルダ名が
`ComfyUI-Model-Manager-Neo` であることを確認してください。

その後 **ComfyUI を再起動**してください。Python 依存（`huggingface_hub`・
`hf_xet`・`modelscope_hub`・`markdownify`）は初回起動時に自動インストール
されます。Web バンドルは `web/` に、Rust コアは `native/native-bin/` に
ビルド済みで同梱されているため、**拡張機能の実行に Node.js も C コンパイラも
不要です** — 対応プラットフォームは[エンジン](#the-engine)の表を参照してください。

## 2. マネージャーの開き方

入口は 4 つ。どれも同じ動作です:

| 入口                                  | 場所                                                     |
| ------------------------------------- | -------------------------------------------------------- |
| **トップバーの「Model Manager Neo」** | ComfyUI トップバー（設定の歯車の隣）                     |
| **旧式メニューボタン**                | 旧スタイルのメニューコンテナ（フロントエンドにある場合） |
| **Extensions メニュー**               | `Extensions → Model Manager Neo`                         |
| **コマンドパレット**                  | `Comfy.ModelManager.Open` コマンド                       |

マネージャーは**非モーダルウィンドウ**です: ComfyUI の上に浮かびますが、
キャンバスは完全に操作可能なままなので、閲覧しながらモデルをグラフへ
ドラッグできます。ウィンドウはタイトルバーでドラッグ移動、辺/隅から
リサイズ、⤢ ボタンで最大化できます。複数ウィンドウを同時に開け、
クリックしたものが前面に来ます。マネージャーウィンドウのタイトルバーは
ライブラリのモデル合計サイズをライブ表示します。

> ローディング表示は**対象パネル内に限定**されます — リクエスト中は
> そのウィンドウだけが暗くぼかされ、キャンバス・トップバー・他のウィンドウは
> 使い続けられます。

## 3. 2 つのレイアウト

ヘッダーの最初のボタン（グリッド ⇄ フォルダアイコン）で切り替えるか、
**設定 → Model Manager Neo → UI → フラット表示**で既定を指定できます。

### フラット表示

全種別の全モデルを 1 つのグリッドに並べ、ツールバーを備えます:

- **検索** — 複数トークンの AND 一致。`*` はワイルドカードとして機能します
  （`*anime*` は `anime` を含むすべてに一致）。トークンはファイル名_または_
  サブフォルダに一致します。
- **種別フィルタ** — `All` または 1 つのモデル種別。
- **並び替え** — 名前 / サイズ / 作成日 / 更新日 / 最近使用
  （モデルを開くかグラフへ追加すると使用が記録されます）。
- **カードサイズ** — Extra Large / Large / Medium / Small、または
  **カスタムサイズ**（幅/高さスライダーのダイアログ。ComfyUI 設定に永続化）。

![フラット表示](../demo-assets/view-flat.avif)

### フォルダ表示

ブレッドクラム付き（各階層にフォルダグリフ）のファイルマネージャ風ツリーです。
ブレッドクラムはルートでは場所を取らず、パスが深くなった分だけ開きます。
フォルダはダブルクリックで入り、ブレッドクラムまたは ↑ ボタンで戻ります。
モデルの右クリックでコンテキストメニュー（**開く**）。ウィンドウが狭くなると
中間の階層が先に省略記号化し、ツールバーは縦積みになります —
フラットビューと同じレスポンシブ規則で、コントロールが切り捨てられることは
ありません。

![フォルダ表示](../demo-assets/view-folders.avif)

検索ボックスの隣の行に **フォルダを追加**（フォルダプラス アイコン）があります:
名前を入力すると、閲覧中のディレクトリ内にフォルダが作成されます
（`_ZNN` / `_DeltaZNN` で終わる名前は ZipNN 用に予約されています）。
同じ行に**並び順**と**カードサイズ**のセレクタもあります: フォルダビューは
「1 つのフォルダにスコープしたフラットビュー + フォルダ専用の追加機能
（親への移動・フォルダ作成・フォルダ圧縮）」という設計なので、モデルカードは
両レイアウトで見た目も挙動も同一です — ノード追加/コピー/ワークフロー/
モデルページのホバー列を含みます。

両レイアウトは**隠しファイルの表示/非表示**ヘッダーボタン
（名前が `.` で始まるファイルとフォルダ）を共有します。

## 4. モデルカード

- **プレビュー** — 画像またはループ動画。プレビューのないモデルはガラスの
  **NO PREVIEW** アートワークを表示します。
- **チップ**（左上） — モデル種別とファイルサイズ。カードに連動して拡縮します。
- **サブディレクトリ ラベル** — 種別ルートより下に格納されたモデルは、
  名前の上に所属サブディレクトリを表示します（両レイアウト共通）。
- **スタートグル**（右上・全カード） — 未スターは輪郭の星、スター済みは
  塗りつぶしの黄色い星。クリックで切り替え、スター済みは常に先頭へ並びます。
- **ZipNN コーナーボタン**（右上・スターの隣） — 1 クリックで、詳細ウィンドウの
  ボタンと同じ確認と進捗表示つきで圧縮（または反転表示の解凍）を実行。
  フォルダカードではフォルダバッチを実行します。
- **フォルダカード** — 手作りのペールターコイズのガラスフォルダ（_**Neo**
  なので青系_）。ホバー中はふわりとフロートし、離れるとすぐに静止へ
  戻ります。種別ルートカードは**その種別の合計サイズ**も表示します。
- **重複警告** — 記録済み SHA256 がライブラリ内の別ファイルと一致するモデルは、
  詳細ウィンドウに重複先のパス付きの赤い警告を出します。
- **スマートコレクション**（フラットビュー） — 現在の検索 + 種別フィルタを
  名前付きコレクションとして保存（ユーザー毎に永続化）し、コレクションメニュー
  から再適用できます。アクティブなコレクションはクリア/削除ボタン付きの
  チップとして表示されます。保存と適用は 1 つのピルボタン
  `[💾 コレクション ▾]` に集約されています: フロッピー部分は独立した
  クリック/キーボードターゲットとして保存ダイアログを開き、残りは保存済み
  コレクションの適用/切替メニューを開きます。
- **衛生スキャン**（ヘッダーボタン・両レイアウト） — 孤立したプレビュー/
  ノートファイル、プレビューのないモデル（エディタへのショートカット付き）、
  空フォルダを列挙するローカル専用の一斉検査（ネットワークもハッシュ計算も
  行いません）。選択したエントリはいつもの Danger 確認を経て削除されます。
- **ホバーアクション**（フラット表示・大カード） — **ノードを追加**・
  **ノードをコピー**・**プレビューからワークフローを読込**・
  **モデルページを開く**（プラットフォームが判明しているときはソースの
  ロゴをボタン背景にまとう）。
- **グラフへドラッグ** — 任意のカードをキャンバスへドラッグ:
  - 空きキャンバスへ: モデル選択済みの対応ローダーノードを生成
  - 既存ノードへ: 一致するコンボ入力へ投入
  - テキストエリアへ **embedding** をドラッグ: `(embedding:name:1.0)` を追記
  - **プレビュー画像**のドラッグ: 埋め込みワークフローを読み込む
- **ダブルクリック / シングルクリック** — モデル詳細ウィンドウを開きます。
- **ツールチップ** — カードにホバーすると絶対パスを表示します。

衛生スキャンは発見事項を 1 つのダイアログに集約し、各エントリはいつもの
Danger 確認を経て削除できます:

![衛生スキャン](../demo-assets/hygiene-scan.avif)

## 5. モデル詳細と編集

![モデル詳細](../demo-assets/model-info.avif)

ウィンドウにはプレビュー（複数プレビューがあればカルーセル）、基本情報
テーブル、2 つのタブが表示されます。

| 行                                  | 意味                                                       |
| ----------------------------------- | ---------------------------------------------------------- |
| Model Type                          | ComfyUI のモデルフォルダグループ                           |
| **Directory**                       | **末尾 `/` 付き**の絶対ディレクトリ — 例: `…/models/unet/` |
| File Name                           | 拡張子を除いた名前                                         |
| File Size / Created At / Updated At | ファイルシステムの事実                                     |

### 閲覧

- **ローカルへダウンロード** — アクション行のダウンロードアイコン ボタンが、
  モデルファイルをライブラリ名そのままに添付として保存します。アクション行
  全体（ZipNN・スター・ハブページ・識別・グラフ操作・ローカルダウンロード・
  編集・削除）は 1 本のインライン横スクロール行の中で同じボタンサイズを
  共有します。
- **Description タブ** — モデルの隣の `*.md` ファイルに保存された Markdown の
  レンダリング表示。リンクは新しいタブで開きます。
- **Information タブ** — モデルについて記録されたすべてのテーブル
  （既定では読み取り専用。編集モードでは鉛筆が**警告の背後で**開き、
  フォームの保存がノートの front‑matter を書き換えます）。ノートの YAML
  front‑matter（Civitai / Hugging Face / ModelScope ダウンロードが書くもの）は
  行へ解析されます: 作者、ベースモデル、全ファイルハッシュ（`AutoV1` …
  `SHA256_12`）、フォーマットと精度、モデルプラットフォーム、クリック可能な
  モデルページリンク、**すべての**プレビュー画像 URL。パーサが知らないキーは
  テーブル末尾にそのまま列挙されます。front‑matter のないモデルは、safetensors
  ヘッダから直接読んだ `__metadata__` ブロックをそのまま表示します —
  何もキャッシュもバックグラウンドスキャンもされません。
- **テンソル セクション**（safetensors モデル） — ヘッダから解析した正確な
  テンソル構成を、Hugging Face の safetensors ビューア風の折りたたみ可能な
  **フォルダツリー**として描画します: ドット区切りのテンソル名はセグメント
  ごとにグループ化され、各フォルダ行はその階層を折りたたみ/展開する
  フォルダアイコン（最初は最大限折りたたまれています）とテンソル数/
  パラメータ数を持ち、リーフ行は名前の末尾 / dtype / shape を保持します。
  非常に大きなノードはリーフをページングし、明示的な _すべて表示_ 操作を
  備えます。ツリーは Rust コアが事前グループ化するため、数万テンソルの MoE
  ヘッダでも即座に開きます。

  ![テンソルツリー](../demo-assets/tensor-tree.avif)

- **モデルページを開く** — アクション行のボタンは、カードのホバー列の双子と
  同じく、ノートにプラットフォームが記録されていればソースハブ（Civitai・
  Hugging Face・ModelScope）のロゴを背景に表示します。

### ハッシュで識別

モデル詳細のアクション行にある**ハッシュ逆引きボタン**（HashReverse
アートワーク アイコン）は、ローカルファイルがどのモデルバージョンかを
Civitai カタログへ問い合わせます: ノートの front‑matter に記録済みのハッシュ
（`AutoV1` / `AutoV2` / `SHA256` / `CRC32` / `BLAKE3`）を先に試し、どれも
当たらなければファイルを 1 パスでハッシュ計算します。ヒット時は解決された
モデル/バージョンがベースモデル・トリガーワード・ファイル一覧とともに開き、
公式 CLI がヒット時に表示するのと同じ `civitai download` コマンドも
（1 クリックでコピー可能に）添えられます。ミスマッチ時は該当なしと
報告されます。問い合わせはファイル単位・オンデマンドです —
ライブラリ全体のスキャンやハッシュ計算は一切走りません。

### 編集

**鉛筆**を押すと編集モードに入ります（ウィンドウがフォームになります）:

![編集モード](../demo-assets/model-edit.avif)

- **Model Type** — この ComfyUI に実際にフォルダがある種別だけのドロップダウン。
- **Directory** — 読み取り専用フィールド + **フォルダボタン**。すべての
  ベースパスとサブフォルダのツリーを持つ、入れ子のフォルダ選択ダイアログを
  開きます:

  ![フォルダピッカー](../demo-assets/folder-picker.avif)

- **ファイル名** — **フォルダ接頭辞**を受け付けます。`subfolder/my-model` と
  入力すると、保存時にモデルは `…/models/unet/subfolder/` へ格納されます
  （無いフォルダは作成されます）。`\ : * ? " < > |` と空 / `.` / `..`
  セグメントは拒否され、パス トラバーサルはサーバ側でも再検査されます。
- **プレビュー** — 単一のギャラリーとして管理されます。編集モードでは
  メインプレビューの隣/下にインラインスクロールのサムネイルストリップが
  現れ、メインの選択・左右移動・単一画像の削除を行えます。
  **青いリング**をまとったサムネイルが、保存時にカードの**メイン**プレビューへ
  昇格するものです（タイルのクリックと ‹ / › 矢印がリングを移動します）。
  ストリップ末尾の点線タイルはローカル画像ファイルを新しいプレビューとして
  追加し（画像は WebP へ変換、動画は形式を維持）、すべてのエントリを削除すると
  プレビューなしの状態になります。編集を開始すると、読み取りモードがどの
  ページを見ていたかに関わらずリングは常に現在のメインに置かれます。
  読み取りモードのページ送りはメインを再指定しません。
- **説明** — ヒントテキストの隣の**編集（鉛筆）アイコン**を押すと Markdown
  テキストエリアが開き、フォーカスを失ったときに保存されます:

- **保存 / キャンセル** — 未保存の変更があるキャンセルはまず確認を求めます。
  保存は 1 回のリクエストを発行し、変わったもの（名前・種別・ディレクトリ・
  プレビュー・説明）はフィールド単位でアトミックに適用されます。
- **削除**（赤いゴミ箱） — 確認ダイアログの後、モデル**と**そのプレビュー・
  ノートを削除します。

## 6. モデルのダウンロード

ヘッダーから**ダウンロード一覧**を開き、次のように進めます:

### ダウンロードタスクを作成

1. **Civitai モデルページ**・**Hugging Face repo/blob/tree**・
   **ModelScope モデルページ**（`www.modelscope.ai`）・**直接ファイルリンク**
   （`.safetensors`・`.ckpt`・`.gguf` 等）を貼り付け、**Enter** または
   検索アイコンを押します。Civitai のミラーホスト `civitai.red` のページ URL は
   Civitai と完全に同じように扱われます。
2. 直接リンクの場合は先に **Model Type** を選ぶ必要があります
   （この ComfyUI にある種別だけが表示されます）。任意の **Subfolder**
   フィールドでファイルをより深く配置できます。
3. Civitai/HF のページは 1 つ以上の**バージョン**と**ファイル**へ解決されます。
   ツールバーでバージョン、エディタでファイルを選びます。

   ![解決済みエディタ](../demo-assets/download-resolved.avif)

   バージョン行の下のエディタは**左にプレビュー・右にギャラリーストリップ**を
   配置し、ファイル選択 + ダウンロード、メタデータエディタ、
   説明/情報タブが下に続くため、ウィンドウがどれだけ狭くても何も
   見えなくならない設計です。

4. エディタでは保存先の種別/ディレクトリ、ファイル名（フォルダ接頭辞可）、
   プレビュー画像 — モデルページが提供する**ギャラリー全体**が保持され、
   カルーセルで選択したままの画像がカードのメインプレビューになります —
   および Markdown 説明を設定できます（Civitai/HF の説明はトリガーワードと
   YAML メタデータを含めて事前入力されます）。
5. **ダウンロード**でバックグラウンド タスクが開始します。プレビューは
   可能ならブラウザ側、そうでなければサーバ側で取得されます。両方失敗しても
   モデルはプレビューなしでダウンロードされます。ダイアログは保存先
   ボリュームの**空き容量**を表示し、ファイルが収まらない場合は警告します
   （バックエンドも拒否します）。

### モデル名検索（マルチプラットフォーム）

入力が `https://` で**始まらない**とき、同じ入力欄はモデル名検索ボックスに
なります: 結果は **Hugging Face**（左）・**ModelScope**（中央）・
**Civitai**（右）から並列に届きます。各行はオーナーのアバター
（またはイニシャルバッジ）、ダウンロード数、2 つのディープリンクを
備えます — オーナー名 → オーナーページ、リポジトリ名 → モデルページ
（ホバーで下線、タップで開く）。行のそれ以外をクリックすると、そのモデルが
エディタへ解決されます。素の `username/repo-name` も受け付けます。
**Enter は常に 1 回で解決します**: 結果内の完全一致 → Hugging Face
リポジトリとしての裸のリポジトリ ID → 最初の非空列の先頭行の順。
結果がまだ無いとき — または画面の結果より新しい入力のとき — Enter は
古い行を解決する代わりに名前検索を（再）実行します。検索中は結果エリアの
中央に「検索中…」スピナーが表示されます。各列はページングもします:
下端までスクロールすると、次のページがあるときだけ**「∨ もっと見る」**
ボタンが現れ、1 クリックでその列の次のページが追加されます。
プラットフォームの非表示と各プラットフォームの**並び順**は
**設定 → Model Manager Neo → 検索** で選べます（既定は Hugging Face
トレンド・ModelScope いいね・Civitai 高評価順）。

![マルチプラットフォーム検索](../demo-assets/search-columns.avif)

### ダウンロード計画と安全チェック

バージョンが解決されると、エディタはドライラン計画を表示します:
保存先パス・宣言サイズ・公開 SHA256・プラットフォーム API キーの設定有無。
Civitai ダウンロードは完了時に公開 SHA256 と照合されます（不一致は
ファイルを削除してタスクを失敗させます）。別種別の同梱ファイル（VAE 等）は
対応するモデルフォルダへ振り分けられます。バージョンのベースモデルが
保存先フォルダの記録済みライブラリと合わない場合や、ペイロードがロード時に
コードを実行し得る pickle/アーカイブ形式の場合には警告が出ます。
キーを設定した全プラットフォーム（Hugging Face・ModelScope・Civitai）の
接続中アカウントがウィンドウ上部に表示されます。

### ライトボックスの生成メタデータ

Civitai 由来モデルのプレビューを拡大すると、左に画像・右に解析済みの
生成メタデータが表示されます: プロンプト、ネガティブプロンプト、サンプラー、
ステップ数、CFG スケール、シード、clip skip、サイズ、ベースモデル、
リソース構成。

### ダウンロード一覧

**外部ダウンロード**と**ローカルアップロード**の 2 セクション。各行は
プレビュー サムネイル、進捗バー、転送済み/合計サイズ、速度、
**一時停止 / 再開 / 削除**コントロールを表示します。削除は部分ファイルと
タスク記録を消します。一時停止したダウンロードは HTTP `Range` リクエストで
再開します。

> 進捗・一時停止・完了はウィンドウを閉じても生き残ります: タスクは
> バックエンドに存在し、websocket で配信されます。

## 7. Hugging Face / ModelScope へのアップロード

ウィザードはまず**アップロード先プラットフォーム**（Hugging Face または
ModelScope）を尋ね、種別/モデル選択を経てアップロードフォームへ進みます。
ModelScope アップロードは常に国際版 `www.modelscope.ai` ドメインと通信します。
リポジトリ作成（パブリック/プライベート）、保存先パス、ライブ進捗表示は
両プラットフォームで動作し、フォルダビューの一括アップロード
（選択フォルダ → 内部の全モデル、サブフォルダ構造を維持）も選ばれた
プラットフォームを尊重します。

先にトークンを設定してください: **設定 → Model Manager Neo → API キー →
Hugging Face API キー**（または `HF_TOKEN` をエクスポート）。ModelScope
アップロードには **ModelScope API キー**（または `MODELSCOPE_API_TOKEN`）を
使います。

ヘッダーから **Hugging Face / ModelScope へのアップロード**を開きます:

1. **アップロード先プラットフォームを選択** — Hugging Face または ModelScope。
2. **モデル種別を選択** — 種別ごとに 1 ボタン。
3. **モデルを選択** — その種別のグリッド。選ぶと保存先パスにモデルの
   相対パスが事前入力されます。
4. **アップロード**:

   ![HF アップロードフォーム](../demo-assets/hf-upload.avif)

   - **リポジトリ ID** — `username/repo-name`。
   - **リポジトリが存在しない場合プライベートで作成** — _作成時のみ_適用。
     既存リポジトリは自身の可視性を維持します。
   - **関連アセット（プレビュー / ノート）もアップロード** —
     `<モデル名>.*` のサイドカー（プレビュー画像・Markdown ノート）を
     モデルと同じリポジトリ ディレクトリへアップロードします。
   - **モデルのノートを README.md としてアップロード**（既定 ON） —
     モデルの Markdown ノートを `<モデル名>.md` の代わりにリポジトリの
     `README.md` としてコミットします。
   - **リポジトリ内の保存先パス** — リポジトリ内のディレクトリ + ファイル名。

**アップロード**を押すと、リクエストは即座に戻り、転送はバックグラウンドで
実行されます — ウィンドウを閉じてもキャンセルされません。進捗表示は
現在のフェーズを名前で示します:

| フェーズ          | 内容                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------- |
| `準備中…`         | トークン確認・リポジトリ検索・アップロード前のネゴシエーション                                                  |
| `ハッシュ中…`     | ローカル SHA256 をネイティブコアで計算（数 GB のモデルでは数分かかり得ます）。**まだ 1 バイトも送信されません** |
| `アップロード中…` | 実際の転送。ライブのパーセント表示                                                                              |

![HF アップロード進捗](../demo-assets/hf-upload-progress.avif)

### 完了時に出るメッセージ

| トースト                                                        | 意味                                                                                                                                                                                           |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **成功** — `path -> repo`                                       | 新しいコミットが作成され、バイトが転送されました                                                                                                                                               |

## 9. フィードバック・ギャラリー・ライトボックス

- **トースト。** すべての操作が結果を報告します: 成功（緑）・警告（黄）・
  エラー（赤）・情報（アクセント）。各トーストは重大度アイコン・色付き左バー・
  右上の**閉じるボタン**を持ち、すべてのダイアログの上の右上にスタックされ、
  寿命が尽きると自動で消えます。

- **プレビューはすべて保持されます。** ダウンロードと保存は、モデルの
  すべてのプレビュー画像を保存します（`<name>.webp`・`<name>.preview.webp`・
  `<name>.preview2.webp` 等）。
- **ページング。** プレビューが複数のとき、プレビュー領域は閲覧モードでも
  編集モードでも **`<` / `>` ボタン**と `i / n` カウンタを表示します。
- **ライトボックス。** プレビューのクリック（タップ）で全画面表示。
  `<` / `>` または矢印キーでギャラリーをページ送りし、`Esc`・背景・
  閉じるボタンで閉じます。

- **環境変数キー。** `private.key` が空で `HF_TOKEN` / `CIVITAI_API_KEY` /
  `MODELSCOPE_API_TOKEN` がエクスポートされている場合、それらのキーは
  `private.key` へ自動採用されます（実際に存在するものだけ）。
- **サイズ超過アップロード。** ComfyUI サーバのアップロード上限
  （`--max-upload-size`、既定 100 MB）を超えるファイルは、素っ気ない
  「HTTP 413」ではなく、上限の上げ方を正確に説明するトーストで報告されます。

## 10. 複数選択と ZipNN 圧縮

### ファイルを選択

両レイアウトのツールバーに**ファイルを選択**トグル（リストチェック アイコン）
があります。ON の間はすべてのカードとフォルダが左上に丸いチェックボックスを
表示し、カードのクリックは開くのではなくチェックします。1 つ選択すると
すぐにウィンドウ下部に一括アクションバーが現れます:

![選択モード](../demo-assets/selection-mode.avif)

- **ワークフローに追加** — 選択したモデルごとに 1 つのローダーノードを生成。
  選択した_フォルダ_は内部の全モデルを（再帰的に）提供します。
- **削除** — Danger 確認の後、選択した全モデルを（プレビューとノートを含めて）
  削除。選択した_フォルダ_は再帰的に削除されます。
- **ZipNN バッチ**（フォルダ選択時） — ZipNN アートワークボタン:
  選択フォルダの一括圧縮/解凍（下記参照）。
- **ZipNN デルタ圧縮**（素のモデルをちょうど 2 つ選択時） —
  ベース/ファインチューン ピッカーを開きます（下記参照）。
- **Hugging Face / ModelScope へのアップロード**（フォルダ選択時） —
  同じアップロード ダイアログで、選択フォルダ内の全モデルを
  （サブフォルダ構造を維持して）一括アップロード。
- **スター**（フォルダ選択時・アイコンのみ） — 選択した全フォルダが
  スター済みなら黄色（押すと全解除）、そうでなければ未スターのものだけを
  スター付けします。
- **選択を解除** — すべてのチェックを外します。モードを抜けても解除されます。

ZipNN バンドルフォルダ（`*_DeltaZNN`、旧式 `*_ZNN`）と通常のフォルダは
同時に選択できません: 一方がチェックされた状態でもう一方を追加すると、
バンドル側の選択が警告トーストとともに解除されます。

### ZipNN 圧縮

`.safetensors` モデルを開くと、プレビューと情報テーブルの間に
**ZipNN アートワークそのもののボタン**があります: 同梱 SVG は自前の
ガラスプレート（ダークモード変種込み）を描画し、ホバーで浮き上がって
明るくなり、ツールチップとスクリーンリーダーに自分を説明します。
押すと、わざと Danger スタイルにしていない確認ダイアログが出た後、
圧縮全体が Rust コアの 1 つのバックグラウンド ジョブとして実行されます
（メモリマップのストリーミング — ピーク RAM はモデルではなく
およそ最大テンソル分）:

- タスク実行中、ボタンは**進捗バー**に置き換わり、いつでもキャンセルできます。
- 成功すると原本ファイルは `<name>.znn.safetensors` へ置き換わります。
  プレビューとノートはリネームに追従し、グリッドは自動で更新されます。
- 圧縮済みモデルを開くと、同じボタンが**反転色**で表示され、アクションは
  _解凍_へ反転します。押して確認すると、素の `.safetensors` が復元されます。

圧縮済みモデルでは、情報テーブルの 1 行の _ファイルサイズ_ も
**元のファイルサイズ** / **圧縮後ファイルサイズ** / **元サイズ比**の 3 行に
置き換わります（圧縮前のサイズは圧縮時にファイルのメタデータへ記録されます）。

![圧縮済みモデルの詳細](../demo-assets/compressed-model.avif)

圧縮ファイルは公式 ZipNN レイアウト（`znn_compressed_vectors` メタデータ、
Huffman 圧縮されたテンソル — Rust コアは**すべての** safetensors dtype を
カバーします。下記の _dtype カバレッジと相互運用_ 参照）に従うため、
`zipnn_safetensors()` パッチ済みローダーは互換帯のファイルを透過的に
読み込めます。圧縮は**可逆かつ検証付き**です: コアは圧縮時に原本の
SHA‑256 を記録し、復元時にインラインで再照合します（不一致時は圧縮ファイルを
保持したまま、復元物を検査用に `.corrupt` として退避）。素の
`.safetensors` は `.znn.safetensors` が書き込まれ検証された後のアトミック
rename でのみ削除され、失敗した実行は部分出力を掃除します。オプトインの
**paranoid モード**（既定 OFF。環境変数 `MM_ZNN_PARANOID=1`）は、原本を
削除する前に解凍し直して比較まで行います。

#### dtype カバレッジと相互運用

Rust コアは **safetensors 0.8 が定義する全 dtype**（22 種すべて）を
2 つの相互運用帯で圧縮します:

| 帯                           | dtype                                                                                                                           | 公式 ZipNN 0.5.4 ツールの挙動                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 上流互換帯（コード 1–30）    | `F32` `F16` `BF16` `F8_E4M3` `F8_E5M2`                                                                                          | Neo のファイルをそのまま解凍可能                                                            |
| Neo 拡張帯（コード 128–146） | `F64` `C64` `I8` `U8` `BOOL` `I16` `U16` `I32` `U32` `I64` `U64` `F8_E4M3FNUZ` `F8_E5M2FNUZ` `F8_E8M0` `F4` `F6_E2M3` `F6_E3M2` | 明示的な `ValueError: Unsupported Dtype` で拒否 — 静かな誤デコードは起きません（CI で実証） |

拡張帯のテンソルを含むファイルは `znn_neo_extended="1"` とマークされます:
Information タブは**Neo Extended** バッジ（相互運用を説明するツールチップ付き）と
格納 dtype の集計**圧縮方式**行（`bfloat16×412, uint8×3, …`）を表示し、
圧縮確認ダイアログは成果物が Neo 拡張形式になることを先に明示します。
上位バイトがすべてゼロの整数テンソル（小さい `int32` インデックス・マスク・
スケールテーブル）はさらにトランケーション モードを使い、全ゼロのバイト平面は
ペイロードから可逆的に落とされます（コンプレッサはテンソル全体でゼロだと
検証した平面のみを落とします）。

<a id="the-engine"></a>

**インストール工程はありません。** エンジンは Neo 独自の**純 Rust コア**で、
リポジトリ内にプリビルド バイナリとして同梱され（`native/native-bin/`）、
素の `import` でロードされます — 対応するすべてのプラットフォームで、
**`pip install` も C コンパイラもネットワークも待ち時間も不要**です:

| プラットフォーム                 | 成果物                                          | 要件                                                       |
| -------------------------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| Linux x86_64                     | `native-bin/linux-x86_64/mm_core.abi3.so`       | glibc ≥ 2.28（Debian 10 / Ubuntu 20.04+）                  |
| Linux aarch64                    | `native-bin/linux-aarch64/mm_core.abi3.so`      | glibc ≥ 2.28                                               |
| macOS（Intel & Apple Silicon）   | `native-bin/macos-universal2/mm_core.abi3.so`   | 1 本の fat binary — Intel macOS 10.12+ / Apple Silicon 11+ |
| Windows x86_64                   | `native-bin/windows-x86_64/mm_core.pyd`         | MSVC ビルド                                                |
| Linux x86_64（フリースレッド）   | `native-bin/linux-x86_64t/mm_core.abi3t.so`     | glibc ≥ 2.28・フリースレッド CPython 3.15+                 |
| Linux aarch64（フリースレッド）  | `native-bin/linux-aarch64t/mm_core.abi3t.so`    | glibc ≥ 2.28・フリースレッド CPython 3.15+                 |
| macOS（フリースレッド）          | `native-bin/macos-universal2t/mm_core.abi3t.so` | 1 本の fat binary・フリースレッド CPython 3.15+            |
| Windows x86_64（フリースレッド） | `native-bin/windows-x86_64t/mm_core.pyd`        | MSVC ビルド・フリースレッド CPython 3.15+                  |

プラットフォーム毎の 1 バイナリが **CPython 3.12 以降**すべてに対応します
（Python Stable ABI）。フリースレッド build は `<tag>t` の **abi3t** バイナリ
（CPython 3.15+・PEP 803）が対応し、ローダーが自動で選びます —
フリースレッド解釈系は通常の abi3 バイナリをロードできません。
公式フォーマットとの相互運用は約束ではなく CI ゲート
です: push のたびに公式 pip `zipnn` 0.5.4 と双方向でクロス検証されます。
表の外側のプラットフォームでも拡張機能はインストールできます — 閲覧・
ダウンロード・ハッシュは純 Python 経路へフォールバックし、ZipNN 操作と
プレビュー再エンコードは静かに失敗する代わりに、エラー トーストでローダーの
正確な理由を報告します。

### ZipNN バッチ圧縮（フォルダ単位）

1 つ以上のフォルダを選択して一括バーの **ZipNN アートワークボタン**を押すか、
フォルダカードのコーナーボタンを使ってください。確認の後、フォルダツリー内の
すべての `.safetensors` モデルが圧縮され — プレビューとノートもモデルに
追従し — すべての圧縮ファイルは**バンドルフォルダ `<name>_DeltaZNN` へ
移動**します（空になった元のフォルダは消えます）。すでにその場で圧縮済みの
モデル（単体ボタン・自動圧縮・旧バージョン由来）は再圧縮されず、そのまま
バンドルへ移動します。バンドルフォルダは密封されています: 中に置けるのは ZipNN コンテンツ（`*.znn.*` モデル・
`*.znn` デルタファイル）だけで、素のモデルのアップロード・ダウンロード・
移動は拒否されます。バンドルの ZipNN ボタンは**反転**しており、押すと
バンドルを**一括解凍**して、バンドル名の元になったフォルダへすべてを移し返し、
空になったバンドルフォルダを削除します。デルタフォルダ
（`<base>_DeltaZNN`）もバンドルです — 反転ボタンは内部の全ファインチューンを
復元します。モデル種別のルートフォルダ（`checkpoints` 等）はバンドルを
**自分の内側**（`<root>_DeltaZNN`）に作ります。種別ルートの兄弟は ComfyUI の
フォルダマッピングの外へ落ちてしまうためです。方向は自動検出されます:
素のモデルがあれば圧縮、バンドルしか残っていなければ解凍。旧バージョンが
作ったバンドル（`<name>_ZNN`）も元の名前へ解凍できます。タスク実行中、
ボタンは内にパーセントを表示する円形リングになります。複数フォルダは
1 回の確認の背後で 1 つずつ実行されます。

### ZipNN デルタ圧縮（ファインチューン）

素の `.safetensors` モデルをちょうど 2 つ（ベース + ファインチューン）
選択して **ZipNN デルタ圧縮**を押してください。ダイアログがどちらの選択が
**ベースモデル**かを尋ね、もう一方がファインチューンになります。確認すると、
**差分だけ**が `<base>_DeltaZNN/<ft>_delta_<base>.znn` に保存され
（通常はファインチューンのサイズの数 %）、冗長になったファインチューン
ファイルは削除されます。デルタのカードボタン（反転アートワーク）は、
ファインチューンモデルをベースの隣に**バイト単位まで正確に**復元し、
空になったデルタフォルダを削除します。復元にはベースモデルがまだ存在する
必要があり、デルタにはファインチューン自身の SHA‑256 が記録されるため、
復元はエンドツーエンドで検証されます。

![ZipNN デルタダイアログ](../demo-assets/zipnn-delta-dialog.avif)

## 11. 設定

ComfyUI の**設定 → Model Manager Neo**:

### API キー

- **Hugging Face API キー** / **Civitai API キー** / **ModelScope API キー** —
  拡張機能の隣の `private.key` にローカル保存され（UI ではマスク表示）、
  `HF_TOKEN` / `CIVITAI_API_KEY` / `MODELSCOPE_API_TOKEN` が環境変数
  フォールバックになります。旧バージョンで ComfyUI ユーザー設定に保存された
  キーは初回起動時に自動移行されます。

### モデル一覧

- **一覧から除外するモデル種別（カンマ区切り）** — その種別をグリッドと
  ピッカーから隠します。
- **隠しファイル（. で始まる名前）を含める** — ツールバーの目ボタンと同じ。
- **モデルフォルダの外部変更を監視する** — 既定 OFF。ON にすると、
  ネイティブコアがすべてのモデルフォルダを監視し（500 ms デバウンス付き）、
  _別の_プログラムが追加/削除したモデル（`models/loras` への `cp`、
  2 つ目のダウンローダ、埋まりゆくマウントボリューム）に対し、30 秒の
  定期再検証を待たずに約 1.5 秒で影響を受けた一覧を更新します。
  ネットワークマウントされたフォルダは自動でスキップされ（inotify 系の
  監視は NFS/SMB 共有からイベントを受け取れません）、Linux の監視予算
  （`fs.inotify.max_user_watches`）が枯渇するとログの警告とともに定期更新へ
  フォールバックします。`MM_WATCH_ROOTS=1/0` が設定を上書きします。監視の状態 —
  稼働中の root・デグレード状態・イベントカウンタ — は
  `GET /model-manager/watch-status` で読み取り専用で配信されます。

### 検索

- **Hugging Face / ModelScope / Civitai の結果を非表示** — モデル名検索の
  プラットフォーム列ごとに 1 トグル（非表示の列には問い合わせません）。
- **プラットフォーム毎の並び順** — 各 API が受け付けるすべての値。
  既定は Hugging Face _トレンド_・ModelScope _いいね_・Civitai _高評価_。

### ZipNN

- **この日数以上未使用のモデルを自動圧縮** — N 日以上触られていないモデルを
  圧縮します（0 = OFF）。
- **ダウンロード完了後に自動圧縮** — ダウンロード完了直後に圧縮します。

### ダウンロード

- **prompt 実行中はダウンロードを一時停止する** — ComfyUI がプロンプトを
  実行中は転送を保留し、後で再開します。

### UI

- **カードサイズ** / **カードサイズマップ** — サイズピッカーの永続化
  （非表示エントリ。カスタムサイズ ダイアログから編集）。
- **フラット表示** — 起動時の既定レイアウト。
- **UI のパフォーマンスマークを記録する（K15）** — 既定 OFF。グリッドの
  再計算/描画とテンソルツリー構築を `performance.mark` で計測し、サンプルを
  リングバッファへ保持します。ブラウザ コンソールで
  `__mmNeoPerf.summary()`（P50/P95/P99、ms 単位）、`__mmNeoPerf.enable()` /
  `.disable()` / `.reset()` を使えます。

## 12. 言語

UI は ComfyUI のロケール（**設定 → ComfyUI → Locale**）に追従し、
**English**・**中文**（簡体・繁體）・**日本語**の完全バンドルを同梱します。
リージョンサブタグ（`ja-JP` 等）は基底部言語へ折りたたまれ、Hant 書記系
タグ（`zh-Hant`・`zh-Hant-TW` 等）は繁體中文バンドルを選択します。それ
以外は English へフォールバックします。

## 13. トラブルシューティング

| 症状                                                    | 原因 / 対処法                                                                                                                                                                                                               |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| マネージャーボタンが表示されない                        | フロントエンドが拡張機能を登録できていません — ComfyUI ログで import エラーを確認し、フォルダ名が `ComfyUI-Model-Manager-Neo` であることを確認してください                                                                  |
| `Hugging Face token not set`                            | 設定（または `HF_TOKEN`）でトークンを設定し、ダイアログを開き直してください                                                                                                                                                 |
| ダウンロードが始まらない                                | URL に認証が必要な場合があります（Civitai のゲート付きモデル）— Civitai キーを設定してください。タスク行にサーバのエラー文言が表示されます                                                                                  |
| 「Failed to update model: PathIndex …」                 | 選択した種別のフォルダがこのマシンに存在しません — ドロップダウンから種別を選び直してください                                                                                                                               |
| UI にスタイルが当たらない / 灰色のボックス              | 古い `web/` バンドルを見ています — `pnpm build` で再ビルドしてください（開発時のみ必要）                                                                                                                                    |
| プレビューが NO PREVIEW                                 | モデルにプレビューファイルがありません — 編集モードで設定してください                                                                                                                                                       |
| ZipNN が「ネイティブコアが利用不可: …」と報告する       | メッセージにローダーの正確な理由が含まれます: [エンジンの表](#the-engine)外のプラットフォーム、または `native/native-bin/<tag>` バイナリの欠損/破損（リポジトリを再クローンしてください）。閲覧とダウンロードは動き続けます |
| フリースレッド Python 3.13/3.14 で ZipNN が利用できない | abi3t（フリースレッド Stable ABI・PEP 803）は CPython 3.15 以降にのみ存在します — トーストにはまさにこの理由が表示されます。GIL build（3.12+）またはフリースレッド 3.15+ をご利用ください。閲覧とダウンロードは動き続けます |
| アニメーション プレビューが静止画になった               | Rust コア以前のバージョンが保存したプレビューは 1 フレーム目に固定化されています。プレビューを保存し直す（編集モード）とアニメ WebP として再エンコードされます                                                              |
